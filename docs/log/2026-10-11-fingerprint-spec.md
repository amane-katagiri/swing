# 絵文字のフィンガープリントの仕様を書く

swing-connect でもダッシュボードと同じ絵文字を出すようになり、SWING 以外の実装が同じ値を出せることを約束する文書が要るようになった。これまでの説明は architecture にしかなく、今のコードの記述なので互換性の約束にならない。

## 決めたこと

- `docs/fingerprint-spec.md` に、実装に依存しない定義として置く。protocol.md はイベントとミラーの決まりの文書で、表示のための目印とは性格が違うので分けた。
- 版を持たせる。版は求め方と絵文字の表の組で、第 1 版は変えない。版はイベントに載らないので、同じ画面で版を混ぜないこと、第 1 版以外を使うならそれを示すことを求めた。
- 表は仕様の本文に 256 行すべてを載せる。正本はコードポイントの列で、文字と Unicode の名前は参考。`web/emoji/list.txt` は表の写しとし、テストで照らす。
- 文字列としての表し方まで決める。各コードポイントの後に U+FE0F を付け、区切り無しでつなぐ。比べるときは U+FE0F を除いて比べる。画像で描くか、間を空けるかは実装に任せる。
- 本人の証明ではないことを要件として書いた（フィンガープリントだけで相手を選ばせてはならない）。
- テストベクタを 3 つ載せ、Rust のテストで仕様の表から読んで確かめる。
- `list.txt` の U+1F5DC の名前が CLDR の短い名前（clamp）になっていたので、Unicode の名前（compression）に直した。行の順番は変えていないので値は変わらない。

## 検証

- `fingerprint.rs` のテストで、一覧が仕様の表と一致すること、仕様のテストベクタのとおりになることを確かめた。
