# リリースの手順のスクリプト化

v0.1.3 のリリースで、手順がその都度の手作業になっていて、タグの種類（v0.1.0 は注釈付き、v0.1.1・v0.1.2 は注釈なし）やリリースノートの書き方がぶれていたので、手順を `packaging/release/` のスクリプトと AGENTS.md に固定した。

## 決めたこと

- 手順は、バージョンを上げる（`bump.sh`）→ push とタグ（`tag.sh`）→ ドラフトの本文の差し替え（`notes.sh`）→ 公開後の tap の更新（`update-tap.sh`）の 4 段に分けた。push・タグ・公開は利用者の了解が要るので、1 本にまとめず段ごとに止まれるようにした。
- タグは注釈付きにそろえる。
- スクリプトは前提（`main` であること、作業ツリーがきれいなこと、`origin/main` より遅れていないこと、バージョンが合っていること、リリースがドラフトかどうか）を確かめ、満たさなければ何もせずに止まる。tap の更新は、ドラフトの添付ファイルがダウンロードできないので、公開済みでないと止まる。
- コミットに付ける trailer は利用者やエージェントごとに違うので、スクリプトには書かず `SWING_RELEASE_TRAILER` で渡す。
- リリースノートは v0.1.2・v0.1.3 の形（要点 → 変更点 → 入手方法。入手方法は Linux・Windows・macOS・Docker Compose）を `notes-template.md` にした。

## 検証

- `shellcheck` と `sh -n`。
- 前提を満たさないときに止まること（バージョンの形、作業ツリーの変更、リリースが無い・ドラフトのまま）を確かめた。`bump.sh` のバージョンの書き換えは、`Cargo.toml` の写しで最初の `version = "..."` だけが変わることを確かめた。
