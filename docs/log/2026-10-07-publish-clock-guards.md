# 公開の時計の確認を、1 つの relay に止められないようにする

公開の前に時計を確かめる処理（未来の日付の版の拒否・relay より進んだ時計の拒否）をレビューし、指摘を直した。

## 決めたこと

- relay より進んだ時計の判定は、答えた relay の `Date` のうち最も新しいものと比べる。どれか 1 つより進んでいれば止める作りでは、時計の狂った relay・古い応答を `Date` ごと返すキャッシュ・わざと古い `Date` を返す relay が 1 つあるだけで、ほかの relay への公開まで止まり、しかも利用者に自分の時計を直すよう案内してしまう。答えたどの relay よりも進んでいるときだけ止めれば、この機械の時計が進んでいるという判定は保ったまま、1 つの relay では止められない。多数決や中央値も考えたが、relay の数が少ない設定では差が出ず、判定の説明も難しくなるのでやめた。
- `created_at` は、今の時刻・MFS にある同じサイトの版 + 1 に加えて、relay から取った自分の前の版の `created_at` + 1 よりも後にする。MFS だけを見ると、別の機械や手で消した版のほうが新しいとき、新しいイベントが relay の持つ置き換え可能なイベントより古くなり、受理されたように見えて何も変わらない。
- そのため、自分の前の版を取るときは未来すぎる `created_at` のものも除かない。relay はそのイベントを、その時刻が過ぎるまで後から来たイベントより優先して持ち続けるので、見えないまま公開すると同じく何も変わらない。前の版が未来すぎるときは、時計を直すか時刻が過ぎるのを待つよう案内して止める。前の版を取れなかったときは、これまでどおり使わずに進む。
- 未来すぎるかどうかは、署名する値（版 + 1）で判定する。版そのもので判定すると、ちょうど境目の版の 1 秒後で署名したイベントが許容幅を 1 秒超える。
- CLI では時計の確認を、増えたファイルの確認（`y/N`）より前に行う。確認して答えた後に時計の問題で止まるのを避ける。relay の時計の問い合わせは前の版の取得と同時に行うので、待ち時間は増えない。add の直前にも MFS を一覧し直して同じ判定をする（問い合わせの結果は使い回す）。確認を待つ間に別の公開が版を増やしても、その版より後の `created_at` になる。
- relay が断った理由を端末に出すときは、ほかの遠隔の文字列と同じく制御文字と見えない書式文字を落とし、長さを切る。
- 未来の日付で断られたかの見分けは語単位で行う。部分文字列で見ると `too` が `tool` に、`old` が `threshold` に当たる。
- 版のディレクトリ名は 10 進の正規形（`n.to_string()` と一致するもの）だけを版として扱う。`0500` や `+500` を版とすると、エラーに出すパスが存在しないものになる。古い版の削除もこれまでどおりそれ以外の名前には触れない。

## 前から決めていたことの理由

- 時計の確認に当たったときのダッシュボードの応答は 400 にしている。422 は確認のモードで止めるもの（本文に `nip05`・`checks` が付く）に、409 は多重実行に使っているため、利用者が直すべき前提の誤りとして 400 にした。
- relay の時計の問い合わせはプロキシを使わない。relay への接続そのものもプロキシを通らないので、同じ相手の時計を測るため。
- 同じ秒の 2 回の公開が同じ MFS のパスを使うと、後の add が先の版を消したり、打ち切られた公開の後片付けが新しい版を消したりする。`created_at` を既存の版より後にするのはこのため。
- 版から 1 秒後で署名したイベントがミラーに未来すぎるとして捨てられるので、未来の日付の版があるときは公開を止める。
- 署名できた後は add した版を消さない。応答を待ち切れなかった relay にもイベントが届いているかもしれないため。

## 検証したこと

- 時計の判定（答えたどの relay よりも進んでいるときだけ止める・最も新しい relay を挙げる）、`created_at` の決め方（前の版を含む・許容幅の境目）、前の版が未来すぎるときの拒否、add より前に止まること、断った理由の表示の整え方、未来の日付で断られたかの語単位の見分け、版の名前の正規形をテストで確かめた。
- `cargo fmt`・`cargo clippy -D warnings`・`cargo test --workspace` が通る。

## 残したもの

- 同じ秒の衝突を避ける仕組みはプロセスの中だけで効く。CLI とダッシュボード、または 2 つの CLI が同時に同じサイトを公開すると、同じ `created_at` を選びうる。
- agent のレプリカ報告の同期が自分の公開した版を読むところは、版の名前をまだ正規形に絞っていない。
