# README の Desktop 画面をアニメーションにする

README の Desktop 画面のスクリーンショットを、マーキー・NEW バッジ・マスコットが動き、コントロール パネルを開いて動かすまでを見せるアニメーションに置き換えた。撮影はスクリプトにして、静止画も同じスクリプトで撮る。

## 決めたこと

- 形式はアニメーション WebP。GitHub の README では、リポジトリ内のファイルを相対パスで `<video>` に指定しても再生されないので、webm や mp4 は使えない。`<img>` のまま動く WebP・APNG・GIF のうち、同じ録画で GIF（パレット化）が 3.2MB、WebP（品質 80）が 1.5MB だったので WebP にした。
- 原寸 1280×800 のまま出して、表示幅は今までどおり `width="900"` で縮める。900px に縮めてから出すとドットフォントがにじむ。
- 10fps。15fps はドラッグがなめらかになるが、サイズが 3 割ほど増える。
- 可逆 WebP にはしない。録画が非可逆の webm で、文字のまわりに乗るノイズがコマごとに変わるため、4MB を超える。
- マウスカーソルは映さない。録画ツールが重ねるカーソルは Windows 風の見た目にならない。
- ループはぴったりにつながない。マスコットが乱数で歩くので、最後のコマ（ダイアログが開いている）から最初のコマへ切り替わる形にした。
- マスコットがダイアログの下を歩くと見づらいので、撮影するブラウザだけ `Math.random` をシード固定で 0〜0.45 を返すものに差し替え、出現位置と歩く先をデスクトップの左側に寄せる。アプリのコードには手を入れない。
- `prefers-reduced-motion: reduce` のときは `<picture>` で静止画（PNG）を出す。静止画は WebP の最後のコマと同じ配置に撮り直した（前の静止画はマスコットがダイアログの近くにいた）。
- 撮影手順が AGENTS.md の表のセルに収まらなくなったので、`docs/assets/capture.md` に移し、表からはリンクだけにした。

## 作ったもの

- `docs/assets/capture-desktop.sh`: デモ環境にログインし、`agent-browser` で `#/desktop` を録画して `ffmpeg` で WebP にし、続けて静止画を撮る。言語とサイドナビの状態は localStorage に入れておく。静止画は、マーキーの文字がダイアログに隠れず全部見えていて、NEW バッジが点灯しているコマになるまで撮り直す。
- `docs/assets/capture.md`: 撮り方の手順と条件。
- `docs/assets/dashboard-desktop.webp`（約 10 秒・95 コマ・1.3MB）と、撮り直した `dashboard-desktop.png`。

## 検証

デモ環境でスクリプトを実行し、WebP のコマを並べて、全コマでマスコットがダイアログに被っていないこと、ダイアログが最後に前の静止画と同じ位置で止まることを確かめた。静止画は、マーキーの文字と点灯した NEW バッジが写っていることを見て確かめた。

あわせて、GitHub で URL の後ろの全角文字までリンクになっていた bare URL（AGENTS.md と `docker/demo/README.md`）を `<...>` で囲んだ。
