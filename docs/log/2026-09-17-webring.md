# 2026-09-17 `swing webring`（Follow Set の相互関係のグラフ表示）

## 目的

plan §17 の「Webring 表示」。Follow Set を集計して、誰が誰を保存しているか（相互か片方向か）をグラフとして表示する。

## 決めたこと

| 決定 | 理由 |
|---|---|
| relay 横断で `#d = swing` の Follow Set を全部取るのではなく、起点（既定は自分）から Follow Set をたどる | Follow Set は誰でも出せるので、全件取得は件数が読めずスパムもそのまま入る。自分から見た近所のグラフで足りる。`replicas` と同じく既定は自分にした |
| 外向き（`p`）だけでなく、`#p` で「自分たちを入れている Follow Set の作者」もたどる | 外向きだけでは自分を保存してくれている人が出ず、Webring として一番知りたい関係が欠ける |
| `#p` の結果は作者を見つけるためだけに使い、辺は作者で取得した最新の Follow Set から作る | relay ごとに持っている版が違うと、`#p` は古い版だけを返すことがある。作者で取り直せば NIP-01 の置き換え規則で最新を選べる |
| 起点から（向きを無視して）つながらないアカウントは表示しない | 上の理由で古い版から見つけた作者は、最新の Follow Set では起点側を指していないことがあり、孤立したノードとして出てしまう |
| 深さは `--depth`（既定 2）。上限の深さのアカウントも Follow Set は取得する | 見つけたアカウント同士の辺を欠かさないため。上限の外にいるアカウントは数だけ出す |
| ノードの名前はサイトイベントの `d`。無ければ縮めた npub。text で名前が重なれば npub を添える | Webring としてはサイト名で見たい。`d` は誰でも名乗れるので、重なったときに区別できるようにする |
| 出力は `text` / `dot` / `mermaid` | 端末ではテキストの一覧で十分で、図が欲しいときは既存のツール（Graphviz、Mermaid を描ける Markdown）に任せる。plan の ASCII 図のような自前レイアウトはしない |
| 双方向の組は text では `↔` の 1 行、dot では `dir=both`、mermaid では `<-->` の 1 本にまとめる | 相互ミラーが一目で分かるようにする |
| NIP-05 の検証や、レプリカ報告の数はグラフに載せない | 表示のたびに外部 HTTP やレプリカ報告の取得が増える。必要なら `sites` / `replicas` で見られる |
| Follow Set の取得は `FollowSetSource` trait にし、テストでは偽物を使う | `ReportRelay` と同じ形。たどり方をユニットテストで確かめるため |
| 件数上限は入れず、todo の DoS 項目に `webring` とたどるアカウント数を追記した | 既存の `fetch_events` の件数上限と一緒に扱う方がまとまる |

## 作ったもの

- `webring.rs`: `Format`、`FollowSetSource`、`crawl`、`build_graph`、text / dot / mermaid の出力、`swing webring`。
- `nostr.rs`: `RelayClient::fetch_follow_set_authors_referencing`（`#p` と `d` で Follow Set を取得し、検証して作者を返す）。
- `main.rs`: `webring` サブコマンド（`--depth`、`--format`、`<key>...`）。
- ドキュメント: architecture（構成・CLI・webring 節・テスト）、README、extensions の「集計の想定」、todo。`protocol.md` の第 7 節は相互関係の解釈だけを定め、検出方法は規定しないので変えていない。

## 検証

- `cargo fmt` / `cargo clippy --all-targets -- -D warnings` / `cargo test`（ユニットテスト 182 件、ほかに `#[ignore]` 11 件）。追加したテスト: たどり方（外向きと内向き、深さの上限、深さ 0）、グラフ（自分への辺・上限の外・つながらないアカウントの除外、Follow Set の無い起点）、text の並びと表示、名前の重なり、dot と mermaid の出力とエスケープ。
- ローカルの nostr-rs-relay で `nostr_relay_integration` の 3 件を通した。追加した 1 件は、`#p` で作者が見つかること、置き換えで外れた作者と別の `d` の作者が出ないことを確かめる。
- 同じ relay とローカルの Kubo（v0.43.1、test プロファイル）で、使い捨ての鍵 A〜E を使って通しで確かめた。A↔B、C→A、B→D、D→E の Follow Set と、A・B・D（2 サイト）のサイトイベントを置いた。
  1. A から `swing webring`: A・B・C（npub 表示）・D（`d.example, d2.example`）の 4 件、`a.example ↔ b.example`、`b.example → d.example, d2.example`、`C → a.example`、上限の外 1 件（E）。
  2. `--format dot` と `--format mermaid --depth 0` の出力を目で確かめた。
  3. C を起点に `--depth 1`: C と A の 2 件、`C → a.example`、上限の外 1 件（B）。
