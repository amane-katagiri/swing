# アカウントの絵文字のフィンガープリントと、webring のノード名の短縮

ダッシュボードの Sites と Webring の画面では、アカウントは縮めた npub かサイト名でしか見分けられなかった。npub の先頭は `npub1` で共通、縮めると似た文字列が並び、サイト名は誰でも同じものを名乗れる。そこで pubkey から決まる 4 つの絵文字（Twemoji の画像）を「フィンガープリント」として npub や名前の前に出すことにした。合わせて、webring のノード名がサイト名を全部つないだ長い文字列になっていたのを、先頭の 1 つと残りの数に縮めた。仕様は [`architecture/dashboard/fingerprint.md`](../architecture/dashboard/fingerprint.md) と [`architecture/webring.md#ノードの名前`](../architecture/webring.md#ノードの名前)。

## 決めたこと

### 色ではなく絵文字

- 色で見分ける案は、並べて区別できる色相がせいぜい 8 つ程度で、アカウントが十数あればすぐ重なる。ダッシュボードはすでに色に意味を持たせている（root ノード、保存状態・NIP-05 のバッジ、エラー）ので、それとも紛れる。
- 絵文字は形と色の両方が違い、1 つで 256 通り、4 つ並べれば一目で別物と分かる。名前を付けて口で言える（「クジラ・イチゴ…」）のも、相手と見比べるときに役に立つ。

### OS のフォントではなく同梱の画像

- 絵文字フォントは OS ごとに絵柄が違い、古い環境では豆腐（□）になる。相手と画面を見比べる用途では、同じフィンガープリントが同じ絵に見えないと意味が無いので、画像を同梱して見た目を揃えた。
- 画像は利用者の選んだ Twemoji。グラフィックは CC-BY 4.0 なので、表示（作者・ライセンス・元のリポジトリ・スプライトにまとめたこと）とライセンス全文を `web/emoji/LICENSE-twemoji.txt` に置き、`LICENSE-PixelMplus.txt` と同じ経路（リリースのアーカイブ・`install.sh`・Windows のインストーラー）で配る。配信するスプライト自体にも先頭のコメントで同じ表示を入れ、ファイル単体で取り出されても表示が付いて回るようにした。ダッシュボードの画面上にクレジットは出さない（利用者の判断）。
- 256 個を 1 枚の SVG スプライト（`web/emoji.svg`）にまとめ、`desktop-icons.svg` と同じく `<use>` で参照する。リクエストが 1 本で済み、同じオリジンなので CSP も変えずに済む。

### 画像の取り元を git のコミットで固定した

- 当初は npm の `@twemoji/svgs` から取る想定だったが、その名前のパッケージは存在しなかった。似た名前の `@twemoji/svg`（15.0.0 で止まっている）と `twemoji-svg` は、どちらも jdecked/twemoji 本体とは別の人が公開しているもので、中身の出どころを確かめにくい。
- そこで、保守されているフォーク jdecked/twemoji のタグ `v17.0.3` のコミットの tar.gz を GitHub から取り、生成スクリプト（`packaging/twemoji/build-sprite.py`）にコミットと SHA-256 を書いて照らすことにした。`python3 -I` で動き、標準ライブラリだけを使う。生成物はリポジトリに入れ、`cargo build` では作らない（ビルドにネットワークや Python を要らないようにするため）。

### フィンガープリントの求め方

- pubkey のバイト列をそのまま使わず、SHA-256 を取ってから先頭 4 バイトを使う。npub の先頭を好みの文字列にした「バニティ鍵」は多く、それらは pubkey の先頭のビットが揃っているので、そのまま切り出すと同じフィンガープリントになる。
- 計算はサーバ側（`src/fingerprint.rs`）で行って DTO に載せる。ダッシュボードは LAN のアドレスから平文の http で開かれることがあり、安全なコンテキストでないと `crypto.subtle` が使えない。JS に SHA-256 を自前で書くより、すでにある `sha2` を使うほうが確か。
- 4 つで 32 ビット。見分けるための目印で、本人の証明ではない（狙ったフィンガープリントの鍵は総当たりで作れる）。画面の `title` と利用者向けの手引きで、本人の確認は npub（と NIP-05）で行うよう伝える。
- 1 つで 8 ビット・256 通りにしたのは、バイトをそのまま番号にでき、取り違えにくい絵文字を選べる数の上限に近いから。

### 256 個の選び方（`web/emoji/list.txt`）

- 候補は Unicode の emoji-data（11.0）から、`Emoji_Presentation=Yes` の 1 コードポイントの絵文字を取り、`Emoji_Modifier_Base`（人や手）・`Emoji_Component`・地域指示子（国旗）を除いて、Twemoji に画像があるものに絞った（約 900 個）。Unicode 11 までにしたのは、古い環境でも `aria-label` の文字が豆腐にならないため。
- そこから手で、人の顔・人物、宗教・政治、暴力・酒・不快な連想のあるものを外し、16px 前後で取り違えやすい組（色違いの丸・ハート・四角、似た果物、似た動物の顔、似た乗り物）は片方だけ残した。残りは動物・植物・食べ物・道具・乗り物・天気など。
- 行の順番が番号なので、出した後は並べ替えない。一覧は Rust（`include_str!`）とスプライトの生成スクリプトの両方が読む 1 つのファイルにした。

#### 出す前の見直し

- 最初の版には 🔑・🔒・🔔・🚦・🚧・🔗 のような、状態やセキュリティの合図に読めるものが入っていた。npub のコピーや NIP-05 のバッジの隣に 🔑 や 🔒 が出ると、鍵の状態や検証の結果を表しているように見える。同じ理由で ⚡・🔋・⭐・📌・🔍・💬・📡 も外した。
- 同じものの変種のかたまり（🌲🌳🌴、🏀🏈⚽⚾🎾、🚌🚑🚒🚗🚚🚜🛵🚲、👟👠👢、🎸🎹🎺🥁、🥐🍞🥨🥞 など）は 16px では見分けにくく、4 つ並べたときに「どの車か」を覚える必要が出る。各かたまりから 1 つ、形がはっきり違うときだけ 2 つにした。
- 空いた分は、形で見分けられる記号（❤・❄・☀・☁・♠・♣・♟・♨・♾・〽・⚛）と、ほかと似ない物・食べ物・動物で埋めた。記号は色ではなく形で見分けられるものだけにし、色違いの変種は入れない。記号の多くは既定がテキスト表示なので、`Emoji_Presentation=Yes` の条件はゆるめ、`aria-label` の文字に U+FE0F を付けた。
- 入れ替えた後の一覧を 16px で並べ、形が似る組（🧽 と 🧀、🥪 と 🧀、🍥 と 🌀、💨 と ☁、🥠 と 🥐、🧴 と 🍼、🥔 と 🥜、♦ と 💎、🦢 と 🦆、💫 と 🌠、⛺ と 🎪、🧂 と 🍼）は片方を外した。まだ出していないので、番号は付け直した。
- さらに、💤（アカウントが休止中に見える）・⚖（法や裁きの連想）・🥭 と 🍐（🍊・🍋 と色しか違わない）を外し、🦗・🍠・🖱・🗜 を入れた（📽 も試したが、16px では 📷 と同じ暗い箱に見えたのでやめた）。
- 虫が苦手な人もいて、フィンガープリントは自分では選べないので、🦗・🐜・🦂・🐛 を外した（🦋・🐝・🐞・🐍 は残す）。代わりに 🦢・🥚・🏢・🔮 を入れた。🦑 は 16px では 🐙 と色しか違わない塊に見え、🌶 は 🦐 と同じ赤く曲がった細長い形に見えたのでやめた。
- 最後に一覧を主題ごと（動物・植物・空と天気・果物と野菜・料理・お菓子と飲み物・お祝いと遊び・芸術と音楽・ゲームと記号・スポーツ・身につけるもの・家の中・学びと道具・場所・乗り物）に並べ直した。順番が番号なので、出した後はこの並びのまま変えない。

### 出す場所

- Sites 画面のアカウントの見出し（カード・テーブル・Unfollowed）と、Webring 画面の `list` 表示の各行・詳細パネル（見出しと報告者一覧）に 4 つ。グラフのノードは円（半径 10）が小さいので、先頭の 1 つを 14px で円の中に重ねる。ポインタのイベントとフォーカスはノードの側が受け、深さで変わる塗りや root の色・破線の枠などの既存の表現はそのまま残す。
- Storage check の表には先頭の 1 つだけ（表の幅を抑える）。フィンガープリントは `/api/status` の各行に `fingerprint` として載せる。この DTO は CLI の `swing status` も API 経由で読む（デシリアライズする）ので、上げた後に `swing up` を再起動するまでは新しい CLI が古い `swing up` の応答を読めない。`#[serde(default)]` で吸収する手もあったが、互換の処置を増やすより再起動で揃うほうを選んだ。ダッシュボードが読み込み済みの `/api/sites` から pubkey で引く案は、ミラー操作で `/api/sites` のキャッシュが捨てられた後に黙ってフィンガープリントが消えるので採らなかった。
- グラフのノード以外のフィンガープリントは `swing-badge` と同じ枠線の角丸で囲む。裸で並べると隣の絵文字やサイト名と境目がわかりにくく、4 つで 1 組だと読み取りにくかった。
- CLI の出力には出さない。端末の絵文字の表示は環境で大きく揃わず、フィンガープリントの価値（同じ見た目で見比べられること）が出ない。

### webring のノード名を「先頭の `d` + 残りの数」にする

- これまではサイト名（`d`）を `, ` でつないでいたので、サイトの多いアカウントは名前が長くなり、グラフでは 16 文字で切れて区別に使えなかった。フィンガープリントで見分けられるようになったので、名前は短くてよい。
- 先頭は `d` の昇順で最初のもの。更新のたびに名前が変わらないよう、作成日時ではなく名前順にした。すべての `d` は API の `names` と詳細パネルに残る。
- CLI（`text`・`dot`・`mermaid`）は `blog.example.com (+2)`。ダッシュボードは先頭の名前（`label`）と残りの数（`more_sites`）を別のフィールドで受け取り、` +2` を付けて出す。グラフでは名前だけを切り詰め、数は切らずに残せる。同じ先頭の名前を持つノードは、これまでどおり縮めた npub を添えて区別する。

## 検証

- `cargo fmt --all`・`cargo clippy --workspace --all-targets -- -D warnings`・`cargo test --workspace` が通る。`fingerprint.rs` のテストで、一覧が 256 の重複の無い 1 コードポイントであること、スプライトの記号が一覧と 1 対 1 であること、既知の pubkey のフィンガープリントを確かめる。`render.rs` と `dto.rs` のテストで、ノード名・`more_sites`・フィンガープリントが載ることを確かめる。
- デモ環境で、Webring のグラフ・`list` 表示・詳細パネル、Sites のカード表示・テーブル表示を、ライトとダークのテーマで表示して確かめた。
