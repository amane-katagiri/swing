# アプリのアイコン（macOS のテンプレート画像と exe のファイルアイコン）

[タスクトレイ](2026-09-24-tray-icon.md) の残りとして、macOS のメニューバーのアイコンをテンプレート画像にし、Windows の `swing.exe` と `swing-tray.exe` にファイルアイコンを埋め込んだ。`swing-tray.exe` のほうには、本体と見分けられるようにタスクトレイのバッジを付けた。構成の現状は [`../architecture/tray.md`](../architecture/tray.md#アイコン) と [`../architecture.md`](../architecture.md#ビルドとリリース)。

## 決めたこと

- **macOS のテンプレート画像は、ロゴの図形をそのまま黒で塗った**: 太陽と 2 本の軌道は重なっていないので、1 色にしても形が潰れない。メニューバーでの実際の大きさ（18pt、Retina で 36px）でも線は 2px ほどある。
- **macOS の停止中は、同じテンプレート画像のアルファを半分にした**: Windows の灰色の版と同じ変換（輝度に変換してアルファを半分）をそのまま使う。黒は輝度 0 のままなので、テンプレート画像としてそのまま使える。
- **`set_icon_with_as_template` を使う**: `tray-icon` 0.25 の `TrayIcon::set_icon` は、macOS ではテンプレートの指定を `false` にして描き直す。状態が変わってアイコンを差し替えるたびに、ただの黒いアイコン（ダークのメニューバーでは見えない）に戻ってしまうので、macOS では `set_icon_with_as_template(.., true)` を呼ぶ。この関数は macOS 以外ではアイコンを変えないので、cfg で呼び分けた。
- **Windows のトレイアイコンは色付きのまま**: Windows にはテンプレート画像の仕組みが無い。
- **exe のリソースは `winresource` で埋め込む**: `build.rs` で `CARGO_CFG_TARGET_OS` が `windows` のときだけ動かすので、Linux の musl ビルドや Docker では何もしない。`default-features = false` にして、使わない `[package.metadata.winresource]` の読み取りのための `toml` 1.x を依存に入れないようにした。
- **`swing.ico` はリポジトリ直下の `assets/` に置いた**: `swing` はルートのクレートなので、`tray/` の下に置くとルートのクレートが子のディレクトリを参照することになる。
- **`swing-tray.exe` のアイコンは本体と分けた**: 同じフォルダに並ぶので、同じアイコンだとどちらがトレイか分からない。ロゴを 88% に縮めて左上に寄せ、空いた右下に Windows の通知領域を模したバッジ（暗い角丸の帯、`^`、黄色の小さな四角）を置いた。バッジには灰色（`#707070`）の縁を付けて、明るい背景でも暗い背景でも帯の輪郭が分かるようにした。白い縁はダークモードで目立ちすぎたので暗くした。16px では `^` が 2px ほどになるが、帯の形で本体とは見分けられる。
- **`swing-tray.svg` は ImageMagick ではなく CairoSVG で書き出した**: ImageMagick の SVG の描画では `stroke` が描かれず、バッジの縁と `^` が消えた。
- **`.ico` の中身は PNG にした**: ImageMagick で書き出すと 256px も BMP になり 300KB を超えたので、Pillow で全サイズを PNG で格納した（17KB）。サイズは 16・20・24・32・40・48・64・256。
- **macOS の実行ファイルにはアイコンを付けていない**: Finder がアイコンを出すのは `.app` バンドル（`Info.plist` の `CFBundleIconFile` と `.icns`）か、拡張属性に持たせたカスタムアイコンだけで、素の Mach-O には埋め込む場所が無い。拡張属性は tar や zip で配ると落ちる。`.app` バンドルにすると LaunchAgent や `service install` の作りも変わるので、todo に回した。

## 作ったもの

- `assets/swing.ico`: `web/favicon.svg` を ImageMagick で各サイズに書き出し、Pillow の `Image.save(format="ICO", sizes=..., append_images=...)` でまとめたもの。
- `tray/assets/swing-tray.svg`・`tray/assets/swing-tray.ico`: `web/favicon.svg` の図形を `<g transform>` で縮め、バッジを足した SVG と、それを CairoSVG で各サイズに書き出して Pillow でまとめたもの（サイズは `swing.ico` と同じ）。
- `tray/assets/icon-template-64.png`: `web/favicon.svg` の `fill` をすべて `#000` にした SVG を ImageMagick で 64×64 の RGBA に書き出したもの（`PNG32:` を付けないとグレースケールで書き出され、RGBA を前提にした `decode_png` で読めない）。
- `build.rs`・`tray/build.rs`: Windows 向けのとき `winresource` でアイコン（それぞれ `swing.ico` と `swing-tray.ico`）とバージョン情報を埋め込む。
- `tray/src/app.rs`: macOS では `icon-template-64.png` を使い、テンプレート画像として出す。
- `Dockerfile`: `build.rs`・`assets/`・`tray/` を COPY するようにした。`tray/` は [タスクトレイ](2026-09-24-tray-icon.md) で workspace のメンバーにしたときから COPY されておらず、`Cargo.toml` の `members = ["tray"]` を読めずに `docker build` が失敗していた。

## 検証

- Linux: `cargo fmt`・`cargo clippy --workspace --all-targets -D warnings` が通る。
- Windows: `cargo xwin clippy --workspace --all-targets --target x86_64-pc-windows-msvc -D warnings` が通る。`cargo xwin build --workspace` で作った `swing.exe` と `swing-tray.exe` の両方に、`llvm-readobj --coff-resources` で ICON 8 つ・GROUP_ICON・VERSIONINFO が入っていること、`swing.exe` には `swing.ico` の、`swing-tray.exe` には `swing-tray.ico` の 256px の PNG が入っていて、互いのものは入っていないことを確かめた。
- Docker: `docker build .` が通る。
- macOS はここではビルドできない（`ring` に macOS SDK が要る）。テンプレート画像の見え方と合わせて、実機での確認を todo に足した。
