# おしらせの種類とブラウザ通知

## 背景

Desktop 画面のおしらせは「ミラーしたサイトの新しい版を保存した」だけだった。publish の完了と、自分のサイトをミラーする人が増えたこともおしらせしたい。Desktop 画面を見ていないときにも気づけるよう、ブラウザの通知も出したい。

## 決めたこと

| 決定 | 理由 |
|---|---|
| 新しいサイトと既存のサイトの更新は区別しない | 区別するには、サイトを初めて保存した時刻を `state.json` に持たせる必要がある（`keep_versions`・`keep_days` で古い版が消えるので、残っている版からは判定できない）。状態の形を変えるほどの価値は無い（ユーザーの判断） |
| `/api/activity` に `latest_published_at` と `latest_replica_report_at` を足し、カーソルが進んだ種類だけ重い API（`/api/publish/sites`・`/api/replicas`）を取り直す | 今の `latest_stored_at` と同じ方式。定期的な確認では relay にも Kubo にも接続しないので、タブの数だけ relay の負荷が増えることはない |
| 2 つのカーソルはメモリにだけ持ち、源はイベントの `created_at`（publish の MFS のディレクトリ名、レプリカ報告の `created_at`）にする | `state.json` の形を変えずに済む。再起動しても agent の最初の poll で同じ値に戻るので、フロントの既読とずれない |
| publish の完了は、agent がレプリカ報告の同期で `publish/<自分>/` を一覧するついでに拾う。ダッシュボードから publish したときは `run_publish` の中ですぐ進める | CLI の `swing publish` も拾える。一覧はもともとしているので、新しい Kubo の呼び出しは増えない |
| 2 つのカーソルは「まだ分からない」（`null`）と「確かめたら無かった」（`0`）を分ける | デモで、他の人の報告が 1 つも無い状態から最初の 1 人がミラーしても鳴らなかった。フロントが `null` を初期化の扱いにしていたので、最初の値を既読の基準として保存するだけになっていた。最初にミラーしてくれた人こそ知らせたい |
| 他の人のレプリカ報告は、poll ごとに `#p=自分` と `since` を付けて取得する（購読は増やさない） | 実装が小さく済む。遅れは最大で `poll_interval` ぶん |
| レプリカのおしらせは、`/api/replicas` の「最新版を持つ報告者」の集合を前回と比べ、新しく加わった人がいるときだけ出す | 報告は `report_ttl / 2` ごとに出し直されるので、カーソルは頻繁に進む。そのたびに鳴らないようにするため |
| watcher は Desktop 画面から切り離してアプリ全体で動かす。タブが裏のときは、ブラウザ通知が使えるときだけ確認する | Desktop 画面の外でも気づけるようにするため。通知を使わないなら、裏のタブで確認しても意味が無い |
| マスコットが見えているとき（Desktop 画面を前面で表示していて、マスコットが 1 体以上いる）はマスコット、それ以外はブラウザ通知 | 同じおしらせを二重に出さないため。前面でも Desktop 画面以外なら通知にする（ユーザーの判断） |
| ブラウザ通知は出しただけでは既読にしない。クリックしたら既読にする。二重に通知しないための「通知済み」の位置は、既読とは別に持つ | 後で Desktop 画面を開いたとき、マスコットがもう一度言えるようにするため |
| コントロール パネルに「通知」タブを作り、確認の間隔を「マスコット」タブから移す（保存するキーはそのまま） | 間隔はマスコット以外のおしらせにも効くようになったため。キーを変えないので、互換のための処置は要らない |
| タスクトレイの OS 通知は今回はやらない | トレイは別プロセスで、ブラウザのイベントは受けられない。OS ごとの通知の依存も増えるので、別の作業にする |
| 種類のオン・オフはマスコット（デスクトップ）とブラウザの通知で別々に持つ（`{mascot: {...}, browser: {enabled, ...}}`）。マスコットが見えているときはマスコット側、見えていないときはブラウザ側で判定し、マスコットが見えているときにマスコット側がオフの種類はどちらにも出さない | デスクトップでは見たいが外の通知は要らない種類がある（レビューの指摘）。ブラウザの通知は「デスクトップを見ていないとき」専用のままにする |
| watcher は、マスコット側でオンか、ブラウザ側でオンでブラウザの通知が使える（オン・許可あり）種類だけを確認する | どちらにも出せない種類の API を取り直さないため。許可が無いのに確認すると、誰も出さないおしらせのために取り直し続ける |
| マスコット側がオフの種類は、watcher が取り直しておしらせを流した直後に、既読を確認したカーソルの値まで進める（ブラウザの通知を出したかどうかに関わらない） | 既読が進む機会がブラウザの通知のクリックしか無くなり、読み込み直すたびに重い API を取り直してしまう（二重の通知は `swing:desktop:notified` で防げるが、取り直しは防げない）。マスコットが後から言い直すことも無いので、流した時点で役目は終わっている |
| 設定は watcher・マスコット・ブラウザの通知が使うたびに `localStorage` から読む（メモリに持って配らない） | Desktop 画面の「通知」タブと Settings 画面のどちらで変えても、その場で効く。読むのは確認とおしらせのたびだけなので軽い |
| ブラウザの通知の設定を Settings 画面にも置く。「表示」パネルの下の独立したパネルで、テーマ・言語と同じくその場で保存する | Desktop 画面を使わない人も通知を使えるようにするため。どちらもブラウザ側の設定で、サーバの設定（保存ボタンで `PUT /api/config`）と混ざらないようにする |
| ブラウザの通知のクリック先は、種類と通知を出した時点のマスコット側のオン・オフで決める。オンなら Desktop 画面（マスコットに任せる）、オフなら保存は 1 件ならリンク・複数なら起動時の画面、publish は Publish 画面、レプリカは Webring 画面で自分のノードを選んだ状態。Webring へは `document` のイベントで頼む | マスコット側がオフの種類は Desktop 画面に行っても何も出ないので、その種類の中身が見られる画面に行く（ユーザーの判断）。オン・オフはクリック時ではなく通知を出した時点のものを使う（既読にしたかどうかと揃えるため）。イベントにしたのは `desktop-notify.js` から `webring.js` を import しないため |
| Settings 画面のパネルには確認の間隔も置き、見出しを「通知」にする。「確認しない」ではブラウザの通知もマスコットのおしらせも来ないことを注記する | 間隔はブラウザの通知にも効くので、Desktop 画面を使わない人も変えられるようにする（ユーザーの判断）。間隔はマスコットにも効くので「ブラウザの通知」という見出しでは狭い |
| `swing:desktop:mascot` の読み書き（`readMascotSettings`・`writeMascotSettings`）と間隔の選択肢を `notify-settings.js` に移す | Settings 画面から `desktop-mascot-settings.js` を読むと、`desktop-mascot.js` → `desktop-updates.js` → `notify-settings.js` と import が循環する。キーの名前は変えないので互換の処置は要らない |
| 設定の読み書き・許可の要求・使えない理由の判定は `notify-settings.js` にまとめ、表示の文面だけを画面ごとに持つ | Desktop 画面は日本語固定、Settings 画面は i18n なので文面は分けるが、判定は 1 か所にする |
| 「通知」タブの種類の文言を「フォロー中のサイトを新しくミラーしたとき」「サイトを SWING に公開（publish）したとき」「自分のサイトが SWING で新しくミラーされたとき」にする | 何が起きたときに鳴るのかを分かるように（レビューの指摘）。公開は既存のサイトの新しい版でも鳴るので「新しいサイト」とは書かない |

## 作ったもの

- `src/activity.rs`: `Activity`（2 つの値を `AtomicU64` の `fetch_max` で持つ。0 は不明）。`AppState.activity` を agent と共有する
- agent: 同期のときに publish の版を記録する（`replicas.rs::held`）。`poll_once` の最後で他の人の報告を取得する（`ReportRelay::fetch_reports_about`）
- `web/desktop-updates.js`: 3 つのカーソルと、種類ごとの既読のキー（`swing:desktop:seen`・`seen-published`・`seen-replicas`）、レプリカの報告者の集合（`swing:desktop:replica-reporters`）。Publish 画面の成功は `swing:published` イベントで受ける
- `web/desktop-notify.js`・`web/desktop-notify-settings.js`: ブラウザ通知と「通知」タブ（種類ごとのオン・オフ、通知を使うかどうか。安全なコンテキストでないときは理由を出して無効にする）
- マスコット: せりふのキー `site-published`・`sites-published-many`・`replica-added`・`replicas-added-many` と、組み込みの既定の文言。種類の違うおしらせは 1 つの吹き出しに合流する。同梱の 3 パックにもせりふを足した

## 検証

- `cargo fmt`・`clippy`・`test` が通る
- デモ環境（`docker/demo/demo.sh up --seed`）で次を確かめた
  - Publish 画面から publish すると、1 回だけおしらせする
  - Sites 画面にいる間の保存はブラウザ通知になり、クリックすると既読になる
  - レプリカ報告は、一時的に立てた agent で新しい報告者が加わったときだけおしらせする
  - 保存とレプリカのおしらせが 1 つの吹き出しに合流する
  - 「通知」タブの見た目と、許可を拒否したとき・安全なコンテキストでないときの表示
- ヘッドレスのブラウザなので、`Notification` はスタブにして呼び出しを確かめた。タブが裏にあるときの確認は、コードの分岐を見ただけで動かしてはいない
