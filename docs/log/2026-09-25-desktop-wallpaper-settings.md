# 2026-09-25 Desktop 画面に「画面のプロパティ」（壁紙設定）を追加

## 対応した項目

Desktop 画面（`#/desktop`）に Win95/98 風の「画面のプロパティ」設定を追加した。

- デスクトップアイコン「画面のプロパティ」（モニタ+パレット+筆のピクセルアート線画）を新設。ダブルクリック／Enter・Space で、SWING Explorer アイコンと同じ活性化方法のモーダルダイアログを開く。
- ダイアログは Win95 風（タイトルバー+閉じるボタンのみ、タブ帯「背景」、下部に OK/キャンセル/適用）。デスクトップ画面全体（タスクバーを含む）の上に浮き、ダッシュボードのサイドナビには影響しない。外側をクリックするとタイトルバーだけが 6 回明滅して「操作を拒否した」ことを示す。
- 「背景」タブ：なし（既定の色）／色／画像の 3 モード。色は Win95 風パレット＋カスタムカラー、画像は「参照...」でファイルを選び、16 ビットハイカラー（RGB565）に量子化してから保存する。表示方法は「中央に表示」「並べて表示」「ページ幅に合わせる」「画面に合わせて伸縮」「拡大して表示」の 5 択。
- 設定は `localStorage["swing:desktop:wallpaper"]` に保存し、ページ読み込み時と Desktop 画面を表示するたびに適用する。

## 決めたこと

| 決定 | 理由 |
|---|---|
| 壁紙は `blob:` ではなく必ず data URL で保持する | CSP が `img-src 'self' data:` で `blob:` を許可していない。同じ理由で `<img>` 経由ではなく CSS の `background-image` に data URL をそのまま入れる形にした |
| 画像は保存前に RGB565（5/6/5 bit）へ量子化し、ディザリングはしない | 「昔のパソコンの壁紙」らしいバンディングをあえて残す狙いの仕様。誤差拡散を入れるとバンディングが消えて狙いと逆になる |
| ダウンスケールは長辺 1920→1280→…→240px の候補を、量子化後の PNG data URL が約 2.5MB を超えなくなるまで順に試す | `localStorage` の実用上限（ブラウザにより 5〜10MB 程度）に対して十分な余裕を残しつつ、小さい画像は無変換で通す（候補の先頭は常に自然サイズ）ため |
| モーダルのオーバーレイは `#view-desktop` の中だけに置き、ダッシュボードのサイドナビの外へは広げない | Desktop 画面は他の画面と独立した「レトロ OS ごっこ」の世界なので、モーダルもその世界の中で完結させる。サイドナビまで塞ぐと Desktop 画面から抜けられなくなる |
| デスクトップアイコンの選択ハイライトのトグルだけ `desktop-window.js` の `selectDesktopIcon` と同じロジックを `desktop-settings.js` 側に小さく複製した（インポートで共有はしない） | `desktop-window.js` は「サイトデータの描画は一切持たず、ウィンドウ管理だけを持つ」設計（`AGENTS.md`/`web.md` に明記）。壁紙ダイアログの都合でこの責務を広げたり、`desktop-settings.js` → `desktop-window.js` → `desktop-settings.js` のような循環を作ったりするより、3 行程度のクラストグルを重複させる方が疎結合を保てると判断した |
| 「色」モードの余白と「画像」モードの余白（中央/並べて/ページ幅に合わせる時のレターボックス）は常にティール（`--desk-teal`）固定にした | 「色」で選んだ色を画像の余白にも流用する案もあったが、状態が 1 つ増えて分かりにくくなるため。既定の見た目に近い、予測しやすい方を選んだ |
| プレビュー（モニタ風のミニ画面）の「中央に表示」「並べて表示」は、プレビュー枠の幅 ÷ `#desk-screen` の実際の幅の比率で画像を縮小して描く。「ページ幅に合わせる」「画面に合わせて伸縮」「拡大して表示」は `background-size: contain/cover/100% 100%` をプレビューと実物で同じ値のまま使う | 等倍系の 2 モードは「実物のピクセルサイズ」が意味を持つので、縮小せずに小さいプレビュー枠へ描くと画像のごく一部しか見えず何も伝わらない。相対サイズ系の 3 モードはキーワード自体が枠のサイズに追従するので、プレビューと実物で計算を分ける必要が無い |

## 実装

- `web/index.html`: デスクトップアイコン `#desk-icon-settings` と、壁紙の背景レイヤー `#desk-wallpaper`（`#desk-screen` の最初の子、`z-index: 0`）、ダイアログ本体 `#desk-dialog-overlay` > `#desk-dialog-display` を追加。
- `web/desktop-icons.svg`: `icon-desk-display-props`（デスクトップアイコン用、白い線画）と `icon-desk-display-props-color`（ダイアログのタイトルバー用、配色版）を追加。
- `web/desktop-settings.js`（新規）: `DesktopSettings`（`init()` / `applyStoredWallpaper()`）を export。ダイアログの開閉・タブ切り替え・フォーカストラップ・Esc/Enter・タイトルバーの明滅・RGB565 量子化・ダウンスケール・プレビュー計算・保存/適用/破棄を持つ。
- `web/desktop.js`: `DesktopSettings.init()` を `DesktopView.init()` から、`DesktopSettings.applyStoredWallpaper()` を `DesktopView.onShow()` から呼ぶよう配線。
- `web/storage.js`: `storage.trySet(key, value)` を追加（既存の `storage.set` は失敗を握りつぶすので、保存の成否をダイアログに返すための別関数）。
- `web/desktop.css`: 壁紙レイヤー・モーダルオーバーレイ・ダイアログ・タブ帯・ボタン・プレビュー用モニタ・パレット等のスタイルを追加。既存の `--desk-*` トークンとベベルの書式（`.desk-window` の 4 レイヤー `box-shadow`）だけを使い、新しい配色は増やしていない。
- `src/dashboard/assets.rs` / `src/dashboard/mod.rs`: `web/desktop-settings.js` を `include_str!` して `GET /desktop-settings.js` として配信するよう登録。`assets.rs` の `style_and_scripts_have_expected_content_types` テストにも追記。
- `docs/architecture/dashboard/web.md`: 「Desktop 画面」節に「画面のプロパティ（壁紙設定）」小節を追加し、`構成` の表・実際に動く要素・`localStorage` キー一覧も更新。`docs/architecture/dashboard.md` の静的ファイル配信表にもルートを追記。
- `docs/assets/dashboard-desktop.png` を撮り直した（新しいアイコンが増えたため）。

後方互換のための処置（旧形式のデータを読むための default・フォールバック・移行コードなど）は入れていない。`normalizeWallpaper()` の防御的パースは、壊れた・想定外の JSON が `localStorage` に入っていた場合に既定値へ落とすためだけのもので、過去のスキーマからの移行コードではない（この機能自体が今回新規のため、移行元となる旧形式は存在しない）。

## レビュー後の修正

上記の初回実装をユーザーがレビューし、同じ回の作業として次を直した（このログは追記のみで、上記の記述はそのときの実装を指したまま変更していない。現状の正確な記述は [`web.md`「コントロール パネル（壁紙設定）」](../architecture/dashboard/web.md#コントロール-パネル壁紙設定) を参照）。

### 直した項目

1. **改名**: デスクトップアイコンとダイアログ見出しを「画面のプロパティ」から「コントロール パネル」に変更。`id`/`class`/SVG シンボル名も `display-props`/`desk-icon-settings`/`desk-dialog-display` 系から `control-panel`/`desk-icon-control-panel`/`desk-dialog-control-panel` 系に揃えて改名した（`localStorage` キー `swing:desktop:wallpaper` は「壁紙のデータ」を指す名前なのでそのまま）。グリフも Win95 の実際のコントロール パネルらしい絵（パネルの中にスイッチ・ダイヤル・スライダーを収め、角にねじ回しを添えた構図）に描き直した。
2. **アイコンの並び替え**: デスクトップアイコンを マイ コンピュータ・SWING Explorer・コントロール パネル・ごみ箱 の順に変更した（`ごみ箱` を末尾へ）。画面上の固定位置ではなく `.desk-icons` 内の DOM 順を変えただけ。
3. **背景色と壁紙画像の独立化（不具合修正）**: 初回実装は「なし（既定の色）／色／画像」を排他的なラジオ（`mode` フィールド）で切り替えていたため、画像を選んだあとに「なし」や「色」を経由してから「画像」に戻すと、画像データ自体が失われて OK で空の画像を保存してしまう不具合があった。`pendingState` の `color`/`image` を完全に独立したキーにし、どちらのモードという概念もやめたことで、この不具合は構造的に起きなくなった。UI も「背景色」と「壁紙」を別々の `<fieldset>` にして常に両方表示するようにし、「既定の色に戻す」ボタン（`color` キーを削除するだけ）と「削除」ボタン（`image` キーを削除するだけ）をそれぞれに付けた。
4. **表示方法を `<select>` に変更**: ラジオ 5 個の横並びをやめ、Win95 風の沈み込みスタイル（`box-shadow` によるサンケン表現）の `<select>` 1 個にした。ラベルは一度「全体を表示（余白あり）」等の案を検討したが、最終的にユーザーの希望で元の 5 択・Windows 7 の日本語表記（中央に表示／並べて表示／ページ幅に合わせる／画面に合わせて伸縮／拡大して表示）のまま据え置いた。ファイル情報の文言も `<幅>×<高さ> ハイカラー (16 ビット)` が括弧の直前で折り返される問題があったため `<幅>×<高さ>・16 ビット` に短縮し、`white-space: nowrap` + `text-overflow: ellipsis`（全文は `title` 属性）に変更した。
5. **プレビューの拡大率が再オープン時に狂う不具合の修正**: `openDialog()` が `syncFormFromState()`（内部で `updatePreview()` → `previewScale()` を呼ぶ）を `overlay.hidden = false` より前に呼んでいたため、プレビュー枠がまだ非表示（`display: none`）でレイアウトされておらず、`getBoundingClientRect().width` が 0 になって `previewScale()` が常にフォールバック値の `1` を返していた。結果として、ダイアログを開き直すたびに「中央に表示」「並べて表示」のプレビューだけが等倍（本来より大きく、枠からはみ出た見た目）で描かれていた。`overlay.hidden = false` と `dialog.hidden = false` を `syncFormFromState()` より前に動かして修正した。
6. **ドラッグ時にタスクバーの上へ重なる不具合の修正**: 初回実装はダイアログを `#desk-dialog-overlay`（`#view-desktop` 直下、タスクバーも含めて画面全体を覆う）の中に入れていたため、ダイアログ自体もタスクバーの上まで自由にドラッグでき、そこに重なって描画されていた。SWING Explorer ウィンドウ（`#desk-window`）はタスクバーに重ならない（`.desk-screen` の `overflow: hidden` に本体が隠れ、タイトルバーもクランプでタスクバー上端に届く位置までしか下がれない）ので、それに合わせてダイアログ本体を `#desk-screen` の中（`#desk-window` の隣）へ移動し、クリックを塞ぐためだけの透明なオーバーレイを `#view-desktop` 直下に残す 2 層構成にした。ダイアログの `z-index`（21）はオーバーレイ（20）より高いままなので、ダイアログ自身の操作性は変わらない。ドラッグのクランプ定数（`TITLEBAR_H` / `MIN_VISIBLE_TITLEBAR`）も `desktop-window.js` と同じ値に揃え、SWING Explorer ウィンドウと同じ位置までしかタスクバー側にはみ出せないようにした。

### 決めたこと（追加分）

| 決定 | 理由 |
|---|---|
| 「既定の色に戻す」は `color` キーを削除するだけで、量子化したティール値を書き込まない | RGB565 量子化を通すとティール `#008080` は `#008284` 寄りにわずかにずれる。「何も保存していない」＝今までどおりの見た目を保証するには、`color` を持たないこと自体が既定を表す必要がある |
| 表示方法の `<select>` に Enter を割り当てず、`onDialogKeydown` の判定で `<select>` も `<button>` と同様にネイティブ処理へ委ねる | Enter は開いたドロップダウンの選択を確定する操作でもあるため、ダイアログの capture ハンドラが先に `preventDefault()` して OK 相当を実行すると、選択の確定より先にダイアログごと閉じてしまう |
| ダイアログを `#desk-screen` の中へ移した際、クリックを塞ぐオーバーレイ（`#desk-dialog-overlay`）は分離したまま `#view-desktop` 直下に残した | ダイアログ本体だけを `.desk-screen` に入れれば見た目のクリッピングは揃うが、モーダルとして「タスクバーを含む画面全体のクリックを塞ぐ」役割まで `.desk-screen` の中に押し込めると、タスクバー分の当たり判定が失われる。役割ごとに層を分けたほうが素直 |

## r3: さらなるレビュー対応

上記「レビュー後の修正」に続けて、同じユーザーレビューの中で見つかった残りの項目を直した。`web.md` は現状記述のみを保つ方針（AGENTS.md）のため、履歴はこのログにだけ残す。

- グリフを大幅に簡略化した（パネル枠 + 大きな棒グラフ + 大きな歯車の 2 要素だけ、線を太く）。前回のスイッチ+ダイヤル+スライダー+ねじ回しの構図は細かすぎて 1x では読めなかったため。あわせて、デスクトップアイコンの「見えない」不具合の報告を調査したところ、実装のバグではなく、`<use href="/desktop-icons.svg#...">` による外部 SVG 参照を Chromium が内部でキャッシュしており、同じブラウザセッション内で `desktop-icons.svg` の中身を書き換えても（サーバは新しい内容を正しく返していても）ページ再読み込みだけでは古い解決結果を描画し続けることがあると判明した（ブラウザを完全に閉じて再起動すると解消する）。今後この SVG を編集して確認するときは、検証用ブラウザセッションを一度完全に閉じてから開き直す。
- 表示方法をネイティブの `<select>` から自前の Win95 風コンボボックス（`role="combobox"` の `<button>` + `position: fixed` の `role="listbox"` な `<ul>`）に置き換えた。角丸のポップアップを OS 依存でしか出せないネイティブ select では Win95 の見た目に揃えられなかったため。キーボード操作（↑↓/Home/End/Enter/Space/Esc）はダイアログの `keydown`（capture）ハンドラの中で、リストが開いている間だけ委譲する形にした（ハンドラが `document` の capture なので、コンボボックス自身に別の bubble リスナーを足しても間に合わない）。
- 長いファイル名がダイアログを横に広げていた不具合を修正。原因はコンテナ側ではなく `<fieldset>` 自体で、`<fieldset>` はどのブラウザでも既定で「中身の min-content 幅より縮まない」特殊挙動を持つため、`.desk-wp-fieldset` に `min-width: 0` を足すまでは中の flex 行がいくら `min-width: 0`/`overflow: hidden` を持っていても効かなかった。`.desk-dialog-body` にも `overflow-x: hidden` を足し、二重に保険を掛けた。
- 画像縮小の質を上げた: `drawImage` の前に `imageSmoothingEnabled = true` / `imageSmoothingQuality = "high"` を必ず設定し、縮小率が大きいとき（目標の 2 倍を切るまで）は 1 回で描かず、毎回ちょうど半分のオフスクリーン canvas を経由して段階的に縮小してから最後に目標サイズへ描くようにした。大きな細かい柄のテスト画像で、単発描画（"high" のみ）と段階縮小を同条件で比較したところ、段階縮小のほうが隣接画素の平均勾配で約 8.5% 滑らかになることを数値で確認した（`std`: 10.21→9.27、平均勾配: 12.57→11.50）。
- アルファも 16 ビットハイカラー量子化の対象にし、1 bit（ARGB1555 のアルファ相当）に丸めるようにした（128 以上を不透明・未満を透明とし、透明になった画素は RGB も 0 にする。PNG 圧縮のためだけで見た目には影響しない）。現在の背景色との合成は行わない。半透明のソフトなグラデーション境界を持つテスト PNG で確認したところ、保存後の PNG のアルファ値は `{0, 255}` の 2 値のみになっており（ソフトエッジは消えて輪郭が硬くなる）、画像はそのままに背景色だけ変えると、透明部分に透けて見える色がその場で追従することをスクリーンショットで確認した。

## r4: タブ・アイコン・位置保持・ファイル名のレビュー対応

同じユーザーレビューの続き。`web.md` は現状記述のみを保つ方針のため、経緯はこのログにだけ残す。

- **タブ+パネルのベベルをやり直した**: 直したつもりの r3 でもタブの右下と本文パネルの右端で影が二重に見える／左右非対称という指摘を受けた。原因は、選択中タブが `box-shadow: inset 1px 1px 0 highlight, inset -1px 0 0 shadow` + `inset 0 -3px 0 face` という「自分の影を自分で塗りつぶす」やり方で本文パネルの上辺と縁を切ろうとしていたが、本文パネル側は別要素として独立に `inset 1px 1px 0 highlight, inset -1px -1px 0 dark-shadow`（1 層だけの簡易ベベル）を持っており、2 つの縁が噛み合っていなかったこと。`.desk-window` や `.desk-dialog-btn` で使っている本来の 4 層ベベル（`highlight`/`dark-shadow`/`face-light`/`shadow` の inset 4 本）を本文パネルにも使うよう揃え、選択中タブは同じ 4 層から下辺の 2 本だけを外して `margin-bottom: -2px` で本文パネルの上辺に重ね、`z-index` を本文パネルより上にすることで、選択中タブの下端と本文パネルの上端が実際に 1 枚の面としてつながるようにした（両者が別々に描いた影が隣り合うのではなく、選択中タブの面が本文パネルの縁を物理的に覆う形）。あわせて `.desk-dialog-body` の右端に出ていた濃い縦線も疑われたスクロールバー分の余白ではなく（`overflow-y: auto` は実際にあふれたときしか場所を取らない。计測でも `scrollWidth === clientWidth` を確認済み）、ダイアログ全体の外枠（`.desk-window` の `border: 1px solid var(--desk-dark-shadow)`）がそう見えていただけだった。ベベルを揃えたことで目立たなくなったので、これ以上の変更はしていない。
- **色を選択の入力を Win95 風の四角い沈み込みスウォッチにした**: `<input type="color">` は `appearance: none` だけでは丸い立体スウォッチが残る（スウォッチ自体が別のシャドウ DOM 疑似要素のため）。Chromium の `::-webkit-color-swatch-wrapper`/`::-webkit-color-swatch`（と Firefox 向けに `::-moz-color-swatch`）を角無し・沈み込みベベルに描き直した。クリックで開く色選択ダイアログ自体は OS 標準のまま。
- **アイコンをふつうの歯車 1 個に描き直した**: r3 のパネル+棒グラフ+歯車の構図もまだ「特に何のアイコンか」判別しづらいという指摘だったため、24px いっぱいに広げた歯車 1 個（リング+太い歯 8 枚+中心の軸穴、ストローク幅 2）だけにした。あわせて、デスクトップアイコンが「見えない」という r3 の報告を再調査した結果は実装のバグではなく `<use href="/desktop-icons.svg#...">` の Chromium 内部キャッシュだったことを踏まえ、今回はブラウザセッションを完全に再起動してから確認した。
- **ダイアログとエクスプローラーの位置保持ルールを統一した**: 調べたところ、エクスプローラーウィンドウ（`desktop-window.js`）は「動かしていない間は毎回既定配置を再計算」「一度動かしたら `userPositioned` が立ち、以降はクランプのみ（リサイズをまたいで保持）」だったが、**close→reopen だけは例外的に `userPositioned` をリセットし、既定配置に戻していた**（`openWindowFromIcon()` の `winState.userPositioned = false`）。一方ダイアログ（`desktop-settings.js`）は `openDialog()` が毎回無条件に `centerDialog()` を呼んでいて、そもそも「動かした位置を覚える」仕組みが無く、かつ開いている間のリサイズにも一切追従しなかった（`ResizeObserver` を持っていなかった）。統一後のルール: 動かしていない間は既定配置（ウィンドウは中央寄せジオメトリ、ダイアログは画面中央）を保ち、開く/閉じる・リサイズのたびに再計算する。一度でも動かすとその位置を覚え、リサイズでは新しい範囲内にクランプするだけ、close→reopen でも位置を保つ（ウィンドウの「close→reopen だけ既定に戻す」という特例を撤廃し、ダイアログ側にはウィンドウと同じ `userPositioned`/`geom` 相当の状態（`dialogUserPositioned`/`dialogGeom`）と `ResizeObserver` を新設）。どちらも状態はモジュールスコープの変数のみで `localStorage` には書かない（フルリロードで消える）。
- **壁紙ファイル名の行を直した**: `.desk-wp-image-filename` が `flex: 1 1 auto`（grow あり）だったため、短いファイル名でも行いっぱいに伸び、`flex: none` のサイズ表示だけが右端に離れて見えていた。`flex: 0 1 auto`（grow だけ 0 にする）に変え、ファイル名は自分の文字幅ぶんだけ使い、長いときだけ縮んで省略記号を出すようにした。
