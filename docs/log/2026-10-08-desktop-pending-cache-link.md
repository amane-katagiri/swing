# Desktop 画面のリンク集で更新待ちのサイトを新しい版の情報で出す

更新待ちのサイトは、前の版の CID・日付・ゲートウェイのリンクに差し替えてリンク集に載せていた。state の `VersionRecord` には `title`・`message`・`url` が無いので、タイトルと `[本家]` は新しい版のまま、日付とリンク先だけが前の版になり、新しい版を待っていることもどこにも出ていなかった。

## 決めたこと

- 日付・アイコン・タイトル・更新メモは新しい版（イベント）のものにする。並び順もイベントの `created_at` で決まる。
- まだ取り込んでいない新しい版は配れないので、タイトルはリンクにしない。リンクでない理由は、タイトルの `title` 属性（「最新版がまだ保存されていません」）で示す。
- 保存済みの前の版は、`[本家]` と同じ並びの `[キャッシュ]` のリンクで開けるようにする。前の版であることは `title` で示す。
- 前の版の `title`・`message` を state に残すことはしない。古い state を読む処置が要るうえ、新しい版の情報を出すならいらない。

## 変えたもの

- `web/desktop.js`: 前の版に差し替える処理をやめ、`buildLinkRow` で更新待ちのときにタイトルをリンクにせず `[本家]` と `[キャッシュ]`（`.desk-link-cache`）を出す。
- `web/desktop-page.css`: `.desk-link-cache` を `.desk-link-honke` と同じ見た目にする。

## 検証したこと

- デモ環境で、保存済みの `bob-zine` に `--url` 付きの新しい版を publish し、`min_update_interval` で取り込まれない更新待ちの状態を作った。Desktop 画面のリンク集で、その行に新しい版の日付・`NEW`・タイトル・更新メモが出ること、タイトルがリンクでなくツールチップが出ること、`[本家]` が新しい版の `url` を、`[キャッシュ]` が前の版のゲートウェイの URL を指すこと、`[キャッシュ]` のリンクが前の版の中身を返すことを確かめた。保存済みのサイトの行は前と変わらない。
