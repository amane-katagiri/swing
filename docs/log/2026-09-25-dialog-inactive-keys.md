# 2026-09-25 非アクティブなダイアログのキー処理とタイトルバーでの再アクティブ化

## 対応した項目

1. コントロール パネルのダイアログを開いたまま、サイドナビへフォーカスを移したり別のページへ切り替えたあとで Esc を押すと、非アクティブな（または見えていない）ダイアログがキャンセルされて閉じていた。`createDialog` の capture `keydown` ハンドラは開いている間ずっと `document` に張られているため。先頭で「フォーカスがダイアログの中に無ければ何もしない」ようにした（Esc/Enter/Tab と `onKey` への委譲すべてが対象）。
2. 非アクティブなダイアログのタイトルバーをクリックしてもアクティブに戻らなかった（本文のクリックでは戻る）。ドラッグのためにタイトルバーの `pointerdown` で `preventDefault()` しており、ブラウザ既定のフォーカス移動が止まっていたため。フォーカスがダイアログの外にあるときだけダイアログ自身へフォーカスするようにした。

## 決めたこと

| 決定 | 理由 |
|---|---|
| キー処理の条件は「`root` がフォーカスを含むか」にする | タイトルバーのアクティブ表示（`scheduleActiveSync`）と同じ条件なので、見た目がアクティブなときだけキーが効く |
| タイトルバーのクリックでは、中の要素にフォーカスがあればそのままにする | SWING Explorer ウィンドウは本文クリックで常に自身へフォーカスするが、ダイアログは入力中の要素を奪わない方が Win95 の作法に近い |
| 起動直後に SWING Explorer がアクティブ表示のまま（実フォーカスは無い）なのは変えない | `hasHadRealFocus` による意図した既定表示のため |

## 検証したこと

デモ環境で、次の挙動を確認した。

- ダイアログにフォーカスがある状態の Esc で閉じる
- サイドナビにフォーカスがある状態の Esc では閉じない。ダイアログ内をクリックしてアクティブに戻せば閉じる
- 開いたまま `#/sites` に切り替えて Esc を押しても閉じない
- Tab / Shift+Tab がダイアログ内で循環する
- 非アクティブ時のタイトルバークリックとドラッグでアクティブに戻る
- 中のボタンにフォーカスがある状態でタイトルバーをクリックしてもフォーカスが奪われない
