# ナビのロゴタイプを整数 px の格子に描き直す

Firefox で Settings 画面を下端までスクロールし、さらに下へスクロールすると、左上のロゴタイプの帯の太さが変わって均等な幅に見えることがあった。上へスクロールすると元に戻る。

## 原因

- ロゴタイプは `viewBox="0 0 560 162"` を高さ 26px で描いていたので、帯の太さは 1.6〜2.9px、帯の端も `15.82` のような半端な位置になっていた。
- `shape-rendering: crispEdges` は帯の上端と下端をそれぞれデバイスピクセルに丸める。帯の端が整数に乗っていないと、ロゴが描かれる縦位置の 1px 未満の端数しだいで、帯の太さが変わる。
- 2 枚のスクリーンショットで帯の太さを測ると、いつもの見た目は 2,1,1,1,1,2,3px、崩れた見た目は 1,2,2,2,2,3,3px だった。縦位置の端数を 0〜0.99px で変えて丸めを計算すると、前者は端数 0.41〜0.46px、後者は端数ほぼ 0 のときに出る。
- つまりナビはふだん 0.4px ほど半端な位置に描かれていて、オーバースクロールのあとに Firefox が境目に揃えて描き直すことがある。どちらの場合も補間によるにじみはなかった。
- ページの高さの端数（4635.73px）は原因ではなかった。`<html>` の高さを整数にしても再現した。

## 決めたこと

- ナビ用のロゴタイプを、1 単位が 1 CSS px の `viewBox="0 0 76 26"` で描き直した。帯の太さは上から 1,1,1,1,2,2,3px、隙間は 1px。横方向の端も整数に丸めた。
- 帯の端がすべて整数 px に乗るので、描かれる位置がずれても全部の端が同じだけ丸められ、帯の太さは変わらない。`position: fixed` への変更はしなかった。
- 候補として、帯 2,2,2,2,2,3,3px／2,2,2,2,3,3,4px／隙間 2px の版も作って比べた。元の「下ほど太い」配分に一番近く、隙間の詰まった 1,1,1,1,2,2,3px を選んだ。そのぶん元より一回り小さい（帯の部分の高さ 17px、幅 76px）。
- 元の形は `docs/assets/swing-lockup.svg` に残し、そちらを正本とした。

## 検証

- headless Chrome で、現行と候補の SVG の中身を 0／0.2／0.43／0.7px ずらして描き、帯の太さを測った。現行はずらす量で太さが変わり、描き直した版はどのずらし量でも同じだった。
