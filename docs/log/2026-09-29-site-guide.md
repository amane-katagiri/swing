# 2026-09-29 IPFS で配りやすいサイトのチェックリスト

## 問題

- README の「自分のサイトを公開する」は `swing publish` の使い方だけで、どんなサイトなら SWING のミラーでうまく配れるかの説明が無かった。
- 普通の Web サーバー向けに作ったサイトは、ルートからの絶対パス・CDN への依存・拡張子を省いた URL などで、ゲートウェイ越しに開くと壊れやすい。
- SWING 固有の挙動にも、作者が知らないと損をするものがある。publish はドットファイルも追加する、ミラーの容量上限は版ごとの丸ごとの大きさで数える、同じ CID でも publish すると新しいイベントが出る、`min_update_interval` の間の版はミラーに残らない、など。

## 決めたこと

| 決定 | 理由 |
|---|---|
| `docs/site-guide.md` を新設し、冒頭にチェックリスト、後に項目ごとの理由を置く | publish の前に見返すときはチェックリストだけで足り、理由を知りたいときだけ下を読めばよい。`mascot-guide.md` と同じく、作る人向けの手引きとして README から分ける |
| 上限の値は「既定値」と明記し、正本は README の設定一覧と `swing.example.toml`・`architecture/agent.md` に置く | 値はミラーする各参加者のローカル設定で、作者の側からは決まらない。値を変えたときに食い違わないよう、AGENTS.md に更新の条件を書いた |
| 1 版の目安を「数百 MB 程度まで」にする | 既定の `max_per_site`（10 GiB）は版ごとの合計で数えるので、`keep_versions`（5）個の版を持ってもらうには 1 版 2 GiB が理論上の上限になる。既定より絞っている参加者もいるので、余裕を大きく取った |
| 変わっていないときの publish の抑止は、手順ではなく方針（出力の差分を見る）だけを書く | 事前に CID を計算する `ipfs add` の組み合わせは、ドットファイルやシンボリックリンクの扱いが publish と違い、同じ CID になる保証が無い |

## 作ったもの

- `docs/site-guide.md`: 中身・サイズ・外部への依存・リンクとパス・再現性と更新の 5 分類のチェックリストと、その理由。
- `README.md`: 「自分のサイトを公開する」から手引きへのリンクと、ドキュメント一覧への追加。
- `AGENTS.md`: ドキュメントの構成の表に `docs/site-guide.md` の役割と更新の条件を追加。

## 検証

- 書いた挙動をコードと architecture で確かめた。ドットファイルを除外しないこととシンボリックリンクを辿ることは `src/ipfs.rs` の `walk`、同じ CID を見送ることと取り込み間隔は `policy::decide`（[`architecture/agent.md`](../architecture/agent.md#ポリシー判定policyrs)）、上限を版ごとの合計で数えることは [2026-09-22 の実容量の回](2026-09-22-actual-storage-size.md)、publish が CID に関わらずイベントを出して古い版を `keep_versions` で消すことは `architecture/cli.md` の publish。
- Kubo v0.43.1（`ipfs/kubo:v0.43.1` のコンテナを `--offline` で起動）で、手引きに書いたゲートウェイの挙動を確かめた。
  - `ipfs add -r` はドットファイルを除外し、`--hidden` を付けたときだけ含める（CID も変わる）。
  - `localhost` のパス形式（`/ipfs/<cid>/`）は `<cid>.ipfs.localhost` のサブドメイン形式へ 301 で転送する。`127.0.0.1` ではパス形式のまま返す。
  - パス形式でゲートウェイのルートからの `/css/style.css` は 404。サブドメイン形式では同じパスが 200。
  - `contact.html` だけがあるとき、`/contact` はパス形式・サブドメイン形式とも 404。ディレクトリ `about/` があれば `/about` は `/about/` へ 301。
  - `Image.png` を `image.png` で指すと 404。
  - `_redirects`（`/old /about.html 301` と `/* /404.html 404`）は、サブドメイン形式では転送と独自の 404 ページがどちらも効き、パス形式では無視されて 404 になる。
