# 2026-09-18 Sites 画面の表示スタイル整理と並び順の修正

## 目的

ダッシュボードの Sites 画面から「リスト」表示を外し、「表」を「テーブル」に改める。あわせて、更新順・pubkey 順が正しく見えない件を調べて直す。

## 調べたこと

- pubkey 順: フロントは並べ替えず `/api/sites` の順（`collect_sites` の `BTreeMap` による hex 順）をそのまま使っていた。画面に出すのは `npub`（bech32）で、bech32 の文字表 `qpzry9x8…` はアルファベット順ではないため、hex 順に並べても npub で見ると順不同に見える。
- 更新順: ロジック（アカウント内は `created_at` 降順、アカウントは最新サイトで比較）は正しかった。デモの seed がすべてのサイトを数秒以内に publish していたため、分単位の表示では同時刻に見え、実質的に同順位の並びになっていた。
- NIP-05: カードは `nip05` の検証結果があればバッジ（`nip05: verified` など）を出す。デモは既定で `SWING_NIP05=off` なので検証結果が無く、バッジも出ない。

## 決めたこと

| 決定 | 理由 |
|---|---|
| Sites の表示スタイルは `cards`（既定）と `table` の 2 つにする | リストとカードの差が小さかった |
| pubkey 順はフロントで `npub` の文字列順に並べ替える | 見えている文字列の順と一致させる。API の並びに依存しない |
| NIP-05 のバッジは `OK`/`NG`/`ERR`/`N/A` の短いラベルにし、説明は `title` で出す | 一目で結果が分かるようにする。短くした分、意味はマウスオーバーで補う |
| Sites の絞り込み欄を最大 28rem まで広げる（狭い画面では画面幅に合わせて縮む） | プレースホルダが途中で切れていた |
| カードはサイト名を 1 行目に単独で置き、バッジは 2 行目にまとめる | 名前と同じ行に並べると、カード幅によってレプリカのバッジだけが中途半端に折り返していた |
| seed の `created_at` は `faketime` で過去にずらす | `swing publish` に作成日時を指定するオプションを足すのはデモのためだけの機能になる。seed 専用のイメージ（`seed.Dockerfile`）に閉じ込める |

## 検証

- `docker/demo/demo.sh down` → `up --seed` で作り直し、`/api/sites` の `created_at` が指定どおり（3 時間前〜60 日前）になっていることを確認。
- `swing:style:sites=list` が残っている場合の読み替えは入れない（オタクくんの判断）。
- `demo.sh down` が `demo.env` の無いときに `couldn't find env file` で失敗していたので、`up` などと同じく空ファイルを作ってから実行するようにした。
- ブラウザで更新順 bob → carol → alice、名前順 alice → bob → carol、pubkey 順が npub の文字列順になることを確認。
