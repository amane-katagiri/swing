# Desktop 画面のマスコットと更新のおしらせ

## 背景

Desktop 画面に、画面の中を動き回るマスコット（デスクトップマスコット）を置きたい。手始めに、定期的な更新の確認とおしらせをできるようにする。複数のアバターや、ユーザーが用意したアバターも使える構成にする。

## 決めたこと

| 決定 | 理由 |
|---|---|
| 置き場所はダッシュボードの Desktop 画面（OS のデスクトップやタスクトレイではない） | すでにある Win95 風の画面の世界観に乗せられる。ブラウザの中で完結する |
| 更新の確認は `GET /api/activity`（`state.json` の `stored_at` の最大値だけを返す）を見て、値が進んだときだけ `/api/sites` を取り直す | `/api/sites` は叩くたびに relay に取りに行き、サーバ側のキャッシュも無い。定期的に叩くと relay の負荷がブラウザのタブの数に比例して増える。`VersionRecord.stored_at` はもともとあったので、relay に行かずに「新しく保存した」ことが分かる |
| `/api/sites` の各サイトに `stored_at` を足す | どの版がおしらせの対象か（前回より後に保存したか）をフロントで判定するため |
| おしらせの対象は、保存済み（`stored`）でリンク先（`gateway_url` か `url`）がある版だけ | relay で見えただけでまだ保存していない版は、開けないのでおしらせしない（ユーザーの判断） |
| 既読（`swing:desktop:seen`）は、吹き出しのリンクを開くか「とじる」を押したときだけ進める。それとは別に、メモリ上に「おしらせ済み」の値を持つ | 伝えたけれど見ていないおしらせを、読み込み直したときにもう一度出すため |
| 初めて開いたとき（既読の値が無いとき）は、その時点の最新を既読にするだけにする | 保存済みの全サイトを一度におしらせすると、おしらせとして意味が無い |
| アバターは宣言だけのパック（`manifest.json` とスプライトシート 1 枚、format 1）にする。JS は入れられない | ユーザーが用意したパックでもスクリプトが動かず、CSP も変えずに済む |
| 表現は、名前付きのコマ送りアニメに、まばたき・口パクのオーバーレイを重ねるところまで（ユーザーと合意）。しめじのような、振る舞いの条件や重みの宣言は後回しにする | 既存のデスクトップマスコットのうち、Win95 の世界観に合うのはスプライトのコマ送り（Neko・eSheep・しめじ・Office アシスタント）。伺か風の表情のオーバーレイがあると、おしらせ係らしく見える。Live2D などのボーンの変形は、ライブラリが重く世界観にも合わない。知らないキーは無視するので、後から拡張できる |
| パックの値に上限を付ける（`fps` 60 まで・コマの表示時間 16〜60000ms・256 コマまで・`dx`/`dy`/`speed`/まばたきの間隔の範囲）。コマ送りは 1 周以上たっていたら周回ぶんをまとめて飛ばす | セキュリティレビューで、`fps: 1e20` のような値で表示時間が極小になり、コマ送りのループが終わらずタブが固まることが分かった。検証と、コマ送り側の両方で防ぐ |
| サーバはパックのファイルをディレクトリのハンドル基準でリンクを辿らずに開き（Unix は `openat` と `O_NOFOLLOW`）、開いたハンドルで種類と大きさを確かめ、上限 + 1 バイトまでしか読まない。ハードリンク・FIFO も拒否する | パスで確かめてから読む作りだと、確かめた後に差し替えられてトークンファイルなどを認証なしで配信しうる（`/mascots/*` は静的ファイル扱いで認証が要らない） |
| シートの画像はヘッダを読んで幅・高さ（1 辺 4096px・総数 2048×2048 ピクセルまで）と形式（拡張子と一致）を確かめる。ブラウザ側でも同じ上限で確かめる | ファイルは小さくても巨大な大きさを名乗る画像で、ブラウザに大量のメモリを展開させられる |
| パックは 32 個に絞ってから読み、見るエントリは 1024 個まで | 大量のパックを置かれても、起動時の読み込みとログが膨らまないようにする |
| おしらせの吹き出しを開いている体があれば、次のおしらせもその体に合流させる | 体の間で順番に回すだけだと吹き出しが 2 つ同時に開き、新しいほうを先に閉じると、もう一方の分まで既読になってしまっていた |
| 同梱のパックは `scale` で大きさを決める（`mochi` は 2、`neko` は 1）。全体の倍率の設定は足さない | ユーザーの判断。パックごとの `scale` で十分 |
| 表示する数は、固定の画面幅ではなく、マスコットの表示幅の合計が画面幅の 1/4 に収まるかで決める | パックの大きさがまちまちでも収まるようにするため |
| 吹き出しは `scale` に関わらず等倍（Desktop 画面のほかの文字と同じ大きさ）のままにする | ユーザーの判断。Win95 のツールチップやアシスタントの吹き出しと同じく、キャラの一部ではなくデスクトップの UI として扱い、ユーザーのパックが混ざっても文字の大きさをそろえる |
| 吹き出しの尾が指す点をパックの `balloon` で指定できるようにする | コマの上のほうが透明なパックだと、コマの上端を基準にすると吹き出しが頭から離れて浮く |
| 当たり判定は不透明な画素だけにする（アルファ 128 以上を 1 ビットのマスクで持つ） | `<div>` の背景画像で描くとコマの矩形全体が当たっていた。当時のデスクトップマスコットもウィンドウを絵の形に切り抜いていて、透明なところはクリックが下に抜けるのが普通だった |
| アニメーションごとに `"flip": false` を指定できるようにし、そのアニメーションに入るときはシートの向きに振り向く | 寝るコマに描いた「z」が、逆向きのときに鏡文字になっていた。文字や左右非対称の飾りを描く作者が選べるようにする。反転しない飾りのレイヤー（位置だけ反転する）は後回し |
| 同梱の 48px のキャラの名前は一般名の `mochi`（もち）にする。見た目はリボンのまま | ユーザーの判断。SWING のキャラクターは改めて作るかもしれないので、名前を空けておく。ロゴのスウッシュを模したアホ毛も試したが、リボンのほうがよいとなった |
| `anchor.y` はフレームの下端（高さと同じ値）を足元にする | 最下段のピクセルの行を指す形（48px なら 47）だと、足がタスクバーに 1px めり込んだ |
| ユーザーのパックは `[dashboard] mascots_dir` のサブディレクトリから起動時に読む。不正なパックは警告を出して飛ばし、起動は止めない | ブラウザからのアップロード（壁紙と同じ `localStorage` への保存）は容量が厳しい。`desktop_page` などの差し替えは読めないと起動を止めるが、パックはいくつも置けるので、1 つが壊れていても残りは使えるほうが自然（ユーザーの判断） |
| サーバ側の検証は、id・マニフェストの大きさと `format`・スプライトのファイル名と拡張子と大きさ・シンボリックリンクの拒否・パックの数の上限までにする。アニメーションなどの中身はフロントの `normalizeManifest` で検証する | 配信するファイルを、ディレクトリにあるものだけに絞れれば十分。中身の検証をサーバとフロントの両方に書くと食い違う |
| 同梱のパックもユーザーのパックも、同じ仕組み（`MascotRegistry`）で `/mascots/index.json` と `/mascots/{id}/{file}` から配信する | 静的なルートと動的なルートが同じパスの下で競合しない。コードの通り道が 1 つで済む |
| コントロール パネルの「マスコット」タブで、表示するパック・確認の間隔・歩き回るか・ひとりごとを言うかを選ぶ。全部のパックにチェックが付いているときは一覧を保存しない（後から足したパックも出る）。1 つでも外すと一覧を保存し、後から足したパックはチェックするまで出さない | 明示的に選んだ人の画面に、知らないマスコットが勝手に増えないようにするため |
| 「確認しない」にしたときは、画面を表示したときやタブが前面に戻ったときも確認しない | 設定の名前どおり、ポーリングを完全に止めるため |

## 作ったもの

- `GET /api/activity` と `/api/sites` の `stored_at`（`src/dashboard/api.rs`・`dto.rs`、`State::latest_stored_at`）
- 更新の確認 `web/desktop-updates.js`（`createUpdateWatcher`・`collectNotices`）
- マスコット本体 `web/desktop-mascot*.js`・`desktop-mascot.css`（パックの読み込み・描画・振る舞い・吹き出し・まとめ役）
- 同梱のパック `web/mascots/mochi/`（48px を 2 倍で表示、リボンのおもち、まばたき・口パク付き）と `web/mascots/neko/`（32px を等倍で表示、6 コマの速歩き）。スプライトは Pillow で描いたもので、描いたスクリプトはリポジトリに入れていない
- 当たり判定（不透明な画素だけ）、吹き出しの位置（`balloon`）、反転しないアニメーション（`flip: false`）
- パックを作る人向けの手引き `docs/mascot-guide.md`
- ユーザーのパックの読み込みと配信 `src/dashboard/mascots.rs`（リンクを辿らない読み込み・画像のヘッダの検査を含む）、設定 `[dashboard] mascots_dir`（`SWING_DASHBOARD_MASCOTS_DIR`）
- コントロール パネルの「マスコット」タブ `web/desktop-mascot-settings.js`・`.css`、共通の Win95 風チェックボックス（`desktop-dialog.css`）、タブ帯のローミング tabindex（←/→・Home/End）
- README の「自分のマスコットを追加する」、スクリーンショット `docs/assets/dashboard-desktop.png` の撮り直し

## 検証

- `cargo fmt`・`cargo clippy -- -D warnings`・`cargo test --workspace` が通る。追加したテストは、`/api/activity` と `State::latest_stored_at`、パックの読み込みの各拒否条件（id・同梱の id との重複・マニフェストの欠落と大きさと JSON と `format`・スプライトのパスの抜け出しと拡張子と欠落と大きさ・シンボリックリンク・上限 32 個・ディレクトリが無い場合）、`/mascots/*` の配信（順序・Content-Type・対象外のファイルの 404）
- 振る舞いのモジュールを Node で 2 万ティック回し、画面の外に出ないこと、落とすと地面に着くことを確かめた
- デモ環境（1280×800 と 420px・390px の幅）で次を確かめた。コンソールのエラーは出なかった
  - マスコットがタスクバーの上端に立つ。ドラッグで持ち上げると宙づりのコマになり、離すと落ちる
  - `swing:desktop:seen` を 0 にして読み込むと、保存済みの 4 サイトが 1 つの吹き出しに新しい順に並ぶ
  - 「とじる」とリンクで既読が進み、読み込み直してもおしらせが出ない
  - 画面の端では吹き出しが下に反転し、画面の中に収まる
  - Tab が吹き出しのリンクと「とじる」に届く
  - 狭い幅ではマスコットが 1 体になる
  - 動きを減らす設定では、止まった 1 コマだけを表示する
  - 「マスコット」タブの各設定が、適用・OK ですぐ反映されて読み込み直しても残る。キャンセルでは破棄される
  - 「確認しない」では `/api/activity` を 1 回も呼ばない
- パックの読み込みの拒否条件（シンボリックリンク・FIFO・ハードリンク・大きさ・エントリ数と個数の上限・画像のヘッダの形式と大きさ）を Rust のテストで、悪意のあるマニフェスト（極端な `fps`・`ms`・`dx`・`speed` など）が読み飛ばされることと、コマ送りが大きな時間差でもすぐ返ることを Node で確かめた
- デモ環境で、透明な画素のクリックが下のリンクに届くこと（iframe の上・左右反転・重なり・吹き出しが開いているとき・タッチのエミュレーション）、吹き出しの尾が頭のすぐ上を指すこと、寝るときに振り向いて「z」が裏返らないこと、ネコの歩きで足が滑らないことを確かめた。Firefox と WebKit では当たり判定を確かめていない
- ユーザーのパックの読み込みはルータのテストだけで確かめた。デモ環境に `mascots_dir` を渡す手段が無いため、画面では確かめていない（`docs/todo.md` に積んだ）
