# 2026-09-19 Desktop 画面とサイトイベントの `title`

## 問題

- ダッシュボードの画面はどれも管理用で、保存しているサイトを「眺める」ための画面が無かった。
- サイトの表示名に使えるのは `d`（ドメインや識別子）だけで、昔の個人サイトのリンク集のような見た目にするには素っ気ない。

## 決めたこと

| 決定 | 理由 |
|---|---|
| サイトイベント（35980）に任意の `title` タグを足す | リンク集に出す表示名が欲しい。NIP-51 などでも `title` タグが表示名に使われている |
| `title` は作者の自己申告で、受信側は信頼しない。保存の判断に使わず、表示するときは `d` を併記する | `d` は NIP-05 で裏付けられるが `title` は誰でも好きに名乗れる。タイトルだけ出すとなりすましに使える |
| `title` は 256 バイト以下・制御文字なし・非空。満たさなければイベント全体ではなく `title` だけを無視する | `url` と同じ扱い。飾りのタグのために版の通知を捨てない |
| 発行側（CLI・ダッシュボード）は前後の空白を落とし、空なら無し、規則に反すれば IPFS や relay に触る前にエラー | 受信側で黙って捨てられるタイトルを発行しない |
| CLI は `swing publish --title`、ダッシュボードの公開フォームにも入力欄 | `--message` と同じ経路に乗せる |
| Desktop 画面をサイドバーの「サイト」の上に置く。既定のルートは `sites` のまま | 見た目重視の画面で、最初に開く画面としての実用性は Sites の方が高い |
| Desktop 画面は古い Windows 風のデスクトップに、ブラウザ風の窓で囲んだ昔の日本の個人サイト風リンク集を出す。配色は固定で、ダッシュボードのテーマに追従しない | 実在感を優先する。ライト／ダークで色が変わると時代の雰囲気が崩れる |
| 一覧に出すのは `stored` なサイト（unfollow 済みで残っているものも含む）。`created_at` の新しい順 | 「持っているサイト」のリンク集なので、フォロー関係ではなく保存の有無で決める |
| 行頭のアイコンは 1 つ。NIP-05 が `mismatch`（✕）→ `error` と未知の値（？）を優先し、それ以外（未検証・`verified`・`not_applicable`）は 7 日以内なら NEW、30 日以内なら UP、どれでもなければ既定の ★ | 飾りのアイコンより、リンク先を信用してよいかの手がかりを先に見せる。`not_applicable`（`d` がドメイン形でなく検証しようがない）は警告ではないので新しさ判定に普通に乗せる。アイコンが無い行は作らない |
| `.desk-status-icon` はどの `data-status` でも同じ外枠（32×14px）。`.desk-link-date` も固定幅+`tabular-nums` | NEW/UP は文字が長く ✕/？/★ は短いので、外枠を統一しないと行ごとに日付・タイトルの開始位置がずれる |
| npub・CID・サイズ・レプリカ数は出さない | 細かい情報は Sites 画面の役目 |
| タイトルのリンク先は Gateway の保存済みコピー、無ければ `url`。両方あれば `[本家]` で `url` も出す。どれも `maybeLink()` で新しいタブに開く | 保存しているものを見せる画面なので手元のコピーを優先する。リンクの開き方は他の画面と揃える |
| リンク集ページ内の文言は UI 言語に関係なく日本語。読み込み中・エラー・空・アイコンの説明だけ i18n する | ページの中身は当時の個人サイトの模写で、翻訳すると成り立たない |
| 訪問者カウンタは `localStorage` の `swing:desktop:visits` を足した飾りの数字 | 永続化やサーバ側の状態を増やさない |
| 窓やタスクバーに実在の製品名・ロゴを使わない（フッタの推奨環境の一文を除く）。窓の名前は「SWING Explorer」 | 雰囲気の模写に留める |
| CSP は緩めない | インラインスクリプトや外部リソース無しで、CSS の描画とインライン SVG の `<symbol>` だけで組めた |
| 窓のタイトルは「リンク集 - SWING Explorer」。デスクトップのアイコンも同じ名前にする | 開き直すためのアイコンだと分かるようにする |
| 窓は移動・8 方向のリサイズ・最小化・最大化・閉じるが動く。位置と開閉の状態は `desktop.js` の変数だけが持ち、保存しない | 触って動く方が実在感が出る。保存しなければ、閉じたままや変な位置のままになってもリロードで既定に戻る |
| 閉じた窓は「SWING Explorer」のデスクトップアイコンのダブルクリックか Enter で開き直す。このアイコンだけ選択と起動ができる | 閉じるボタンを動かす以上、戻す手段が要る。当時のデスクトップの作法に合わせる |
| 効果の無い飾り（他のデスクトップアイコン・スタートボタン・アドレス行・ステータスバー・タスクバー・トレイ）は通常の矢印カーソル・選択不可・クリック不可。メニューバー・ツールバーはホバーにだけ反応する（下記追記参照）。`cursor` と `user-select` は `#view-desktop` に 1 回だけ書いて継承させる | 押せそうに見えて何も起きない要素を減らす。`#view-desktop *` で書くと ID の詳細度が勝って、ボタンやリサイズハンドル側の上書きが効かなかった |
| タイトルバーのボタンとタスクボタンは `<button>` にし、`aria-label` と `title` を i18n する。グリフは 16×14px のボタンに 2px の線、最大化は上辺だけ 2px | 実際に押せるものは支援技術にもボタンとして伝える。元のグリフは細すぎた |
| スタートボタン・タイトルバー・タスクボタンのアイコンは SWING のマークを黄・赤・緑の 3 色に塗り分けたもの | グラデーションの四角より SWING の画面だと分かる。灰色の地で見分けやすい色にした |
| トレイに音量・ネットワーク・ミラー中を模した飾りのアイコンを 3 つ置く | 時計だけでは寂しい |
| `.desk-page` のスクロールバーを `::-webkit-scrollbar` で当時の見た目にする。矢印は `data:` の SVG。Firefox は `scrollbar-color` だけ | スクロールバーだけ今風だと浮く。`data:` の画像は既存の CSP（`img-src 'self' data:`）で許されている。Chromium は `scrollbar-color` を書くと `::-webkit-scrollbar` が効かなくなるので `@supports` で分ける |
| Desktop 画面のときだけ `.swing-shell` の高さを `100dvh`（`100vh` にフォールバック）に固定し、`#view-desktop` を縦の flex にしてタスクバーを最下端に置く。760px 以下では `.swing-page-footer` も隠す | 固定の高さ指定では背の高い画面で下に空白が出た。狭い幅ではフッタの分だけページと窓の中の二重スクロールになった |
| 実際に押せるタイトルバーのボタン・タスクボタン・「更新」ボタン・デスクトップアイコンも `cursor: pointer` にはせず矢印のまま。矢印以外が出るのは本文中のリンク（`pointer`）とリサイズハンドルだけ。タイトルバー自体も `cursor: move` にしない | Windows 95 の実機がそうだった。ドラッグできる/できないをカーソルの見た目で予告しない代わりに、Web 的な「押せそうな見た目」も足さない |
| 閉じるボタンの × はインライン SVG（8×7px、`shape-rendering="crispEdges"`、1×1px の `<rect>` を軸に沿って 13 個並べる）で描く。ボタン高さ 14px に対しグリフ高さ 7px（奇数）なので `align-items: flex-start` + `margin-top: 3px` で整数オフセットに固定する | `rotate(45deg)`/`rotate(-45deg)` の 2 本の棒で組んでいた旧実装は斜め線がアンチエイリアスで滲む。中央寄せの単純な flex だと 0.5px 単位のずれが出るので明示オフセットにした |
| リサイズの当たり判定（南東ハンドル、ウィンドウの角の外側にもはみ出す）と、見た目のサイズグリップ（`.desk-grip`、ステータスバー右下 12×12px、ウィンドウ枠の内側）を別要素に分けた。グリップはインライン SVG の高さ 1px の `<rect>` で、白 1px + 灰色 2px の斜めの筋を 3 本描く（当時の画面のスクリーンショットからドットを拾った）。最大化中とナロー幅では非表示 | 旧実装は当たり判定と見た目を同じ要素の斜めストライプ背景で兼ねていて、見た目がウィンドウの角の外にはみ出していた。筋はグラデーションでなく `<rect>` でないと縁が滲む。最初は点を並べた形にしたが、当時の実物は斜めの筋だった |
| デスクトップアイコンの選択状態は、アイコン+ラベルの矩形全体を囲う枠をやめ、ラベルの文字だけ紺地に白文字、フォーカス時の点線もラベルの文字にだけぴったり沿わせる。アイコングリフの白い線は選択中だけ水色寄りに変える。タイル本体には `outline: none` を明示する | 本物の Windows 95/98 は全体を囲う半透明の箱を描かない。`outline: none` を忘れるとブラウザ既定のフォーカスリングがタイル全体に出てしまう |
| アドレス行をツールバーから独立させ、専用の行（`アドレス(D)` ラベル+URL、間に彫り込み線）にする。ラベルは `white-space: nowrap; flex: none`、URL 側は `flex: 1 1 auto; min-width: 0` + 省略記号。メニューバー・ツールバー・ステータスバーの各要素にも `white-space: nowrap` を足す | ツールバーの中に同居させていると、ウィンドウ幅を絞ったときにラベルの「アドレス(D)」が折り返して行の高さが伸びた |
| 既定（初回表示・アイコンからの再オープン）のウィンドウ位置は `.desk-screen` の中で左右対称に中央寄せする。ユーザーが一度も動かしていない間はコンテナのリサイズ（サイドバー開閉など）のたびに中央寄せをやり直し、一度でも動かす/リサイズすると以降はクランプだけにして中央寄せに戻さない | 旧実装はアイコン列を避けるため左マージン 108px 固定・右マージンは残り全部という非対称な既定位置になっていて、特に横長画面で右に偏って見えた |
| 最大化中のタイトルバーを 4px 以上ドラッグすると最大化を解いて、そのまま移動に入る。窓はタイトルバー上の横位置の割合を保ってポインタの下に置く | 今の Windows の作法で、当時には無いが、最大化した窓を動かそうとして何も起きないよりよい。4px はダブルクリックの手ぶれで外れないための遊び |
| 最大化中はリサイズのハンドルを `display: none` にする | JS はリサイズを止めていたが、ハンドルが残っていて窓の端でカーソルだけ変わっていた |
| 開けないデスクトップアイコン（マイ コンピュータ・ごみ箱）もクリックで選択だけはできる。選択は 3 つのうち 1 つ | 当時のデスクトップはどのアイコンも選択できた。無反応よりも手触りがある。「効果の無い飾りはクリック不可」の例外にする |
| 「SWING Explorer」のアイコンは星の線画をやめ、SWING のマークを白一色で塗ったもの（`icon-desk-swing`） | 窓やスタートボタンと同じマークだと、何を開くアイコンか分かる。デスクトップの他のアイコンが白なので色は付けない |
| トレイの音量・ネットワーク・ミラーの 3 アイコンを、16×16 の整数グリッドに乗る `<rect>` だけで組む Win95/98 風ドット絵（16 色 VGA パレット、黒 1px 輪郭）に描き直す。表示サイズも 16×16px に統一し、Start ボタン・タイトルバー・タスクボタンの SWING マークも同じ 16×16px に揃える | 最初のトレイアイコンは滑らかなベクター画で、太さも配色もばらばらで浮いていた |

## 検証

- `cargo fmt` / `cargo clippy --all-targets -- -D warnings` / `cargo test`（243 passed, 11 ignored）。
- デモ環境（`docker/demo/demo.sh up --seed`）で Desktop 画面を 1440×900、サイドバー折りたたみ、390×844 で表示して確かめた。コンソールに CSP 違反やエラーは無い。NEW・UP・既定のアイコンはシードのデータで、NIP-05 の ✕・？ はデモが `SWING_NIP05=off` で該当データを作れないため、ブラウザ上で `cache.sites` を差し替えて `DesktopView.render()` を呼んで確かめた。読み込み中・エラー・空の表示は `/api/sites` を遮断して確かめた。
- 後方互換のための処置は入れていない。`title` は任意のタグの追加だけで、`state.json` の形は変えていない。
- 窓の操作は `agent-browser` で合成したポインタ・マウス・キーのイベントを実際の要素に送って確かめた: 移動、8 方向のリサイズと画面端での制限、最小化とタスクボタンでの復元、最大化と復元、タイトルバーのダブルクリック、閉じてアイコンのダブルクリックと Enter で開き直す、サイドバーの開閉への追従。1440×900・1440×1400・390×844 でページのスクロールが出ないこと、飾りと操作できる要素の `cursor` / `user-select` / `pointer-events` の計算値、全行で日付とタイトルの左端が揃うこと、アイコンの 7 通りの分岐も確かめた。
- スクロールバーの見た目は確かめられていない。検証に使ったブラウザがオーバーレイスクロールバーを強制していて `::-webkit-scrollbar` の描画が出ない。CSS がエラー無く読まれていることだけ確かめた。

## 追記: Gateway の既定を `localhost` にした

| 決定 | 理由 |
|---|---|
| `[dashboard].gateway` の既定を `http://127.0.0.1:8080` から `http://localhost:8080` に変える。デモ環境も `http://localhost:18080` | Kubo は `localhost` ではサブドメイン Gateway として働き、`/ipfs/<cid>/` を `<cid>.ipfs.localhost` へ移す。サイトごとにオリジンが分かれ、`/style.css` のようなルート相対のパスも壊れない。`127.0.0.1` のパス Gateway ではどちらも成り立たない。Desktop 画面でリンクを開く機会が増えるので既定を直した |

- 検証: デモの Kubo に `Host: localhost:18080` で `/ipfs/<cid>` を要求し、301 でサブドメインへ移ることを確かめた。

## 追記: ツールバー/トレイのドット絵、工事中の具体化、バナー画像化、日本語固定

| 決定 | 理由 |
|---|---|
| メニューバー・ツールバーの装飾ボタンはホバーにだけ反応する（IE4 のフラット coolbar。静止時は平面、`:hover` で 1px の立ち上がりベベル、`:active` は付けない）。実際に押せる「更新」だけ同じホバーに加え `:active` の沈み込みも付く | 触ったときの手触りを増やす一方、クリックしても何も起きないのは変えない（クリック不可・非フォーカス・矢印カーソルは維持） |
| トレイ・ツールバーのアイコンは全部 16×16 のドット絵（16 色 VGA パレット、黒 1px 輪郭）にそろえる。ツールバーは戻る/進む（緑の矢印）・中止（新設、赤丸+白 ✕、装飾のみ）・更新（緑の 2 本弧）・ホーム（赤屋根の家）、トレイの音量は黄色いスピーカー+段付きの弧、ミラーは SWING オービットマークのドット絵版（黄色い中心+右上の赤い弧と赤いドット+左下の緑の弧と緑のドット）に描き直す | 旧ツールバーはテキスト+記号（◁ 戻るなど）だけ、旧ミラーアイコンは斜めに並べた 3 つの四角で何を表しているか読めなかった |
| マイ コンピュータのグリフを汎用モニタ（`icon-desktop` 流用）からブラウン管+横置き本体+フロッピースロット+LED の専用シンボル（`icon-desk-mycomputer`）に差し替える。他の 2 つと同じ白い線画スタイルを踏襲し、サイドナビが使う `icon-desktop` 自体は変えない | 「デスクトップ」の意味が伝わらない汎用モニタより、当時の「マイ コンピュータ」アイコンに近い実体のある形にする |
| 縞模様に「工事中」とだけ書いた `.desk-construction-bar` をやめ、マーキーの下にサイト内メニュー（`[ トップ ][ プロフィール ][ 日記 ][ 掲示板 ][ リンク集 ]`）を置く。`リンク集` だけ現在地（非リンク、太字）、残りは未実装ページとして `<a>` にせず工事中サインのドット絵アイコン+ゆれ子の声の断り書きを添える | 「工事中」単体では何が工事中か分からない。具体的な行き先（存在しないページ）に紐付けることで当時のリンク集らしい導線になる。存在しないページへの `<a>` は作らない |
| フッタのバナーを CSS 描画の箱から実物の 88×31 PNG（`/desktop-banner.png`）に差し替える。右クリック保存できる、リンクにはしない | 「バナーはご自由にお持ち帰りください」の一文を文字どおり成立させる |
| Desktop 画面の中で画面に見える文字列（ステータスバー・読み込み中/エラー/空・マーキー・ツールチップ類）を UI 表示言語の設定から切り離し、すべて固定の日本語にする。`i18n.js` の `desk*`/`desktop*` キーは `en`/`ja` 両方から削除し、`desktop.js` 内の `DESK_TEXT` 定数と `index.html` の直書きに置き換える。ARIA ラベルも同じ理由で固定日本語にそろえ、`#view-desktop` に `lang="ja"` を付ける | 90 年代の日本の個人サイトのパスティーシュは翻訳が効かない。ページ本文は元々日本語固定だったが、UI 言語を英語にするとステータスバーやツールチップだけ英語になって統一感が崩れていた。`aria-label` だけ i18n・本文は固定という使い分けは一貫性が無く複雑になるため、ARIA も含めて固定日本語で統一する |

## 検証（追記）

- `cargo fmt` / `cargo clippy --all-targets -j 3 -- -D warnings` / `cargo test -j 3` を実行（結果は本文の「検証」欄を参照）。
- デモ環境で 1440×900・320×240・390×844 を確認し、ツールバー/トレイ/工事中サイン/マイ コンピュータ/バナーの見た目をスクリーンショットで確認した。UI 言語を英語に切り替えても Desktop 画面に英語が出ないことを確認した。
- トレイのミラーアイコンは、弧と点を斜めに並べた形では 16px で何の絵か読めなかったので、バナーと同じ「黄色い中心を赤と緑の弧で上下から囲む」形に描き直した。スタートボタンの文字は `white-space: nowrap` にした（窓ではなく画面を 320px まで狭めるとタスクバーが 2 行になっていた）。
- 中止・更新・ホームのドット絵を描き直した（中止の ✕ が円からはみ出して切れ、更新は矢じりが無く弧にしか見えず、ホームは屋根が壁からずれていた）。マイ コンピュータはモニタを大きくして台を短くした。メニュー項目は上下の余白を 3px / 1px にした（日本語フォントは字面が行の上寄りに乗るので、均等な余白だとホバーの枠の中で上に寄って見えた）。
- 更新ボタンだけホバーで背景を明るくしていたのをやめた。枠の白いハイライトが背景に溶けて、他のボタンと違い枠が無いように見えていた。
- 更新のアイコンに黒 1px の縁を付けた。ツールバーの他の 4 つは縁があり、更新だけ無くて浮いていた。
- 更新のアイコンは上下の矢印の間を 2px 空けた。縁を付けたら 2 本の縁同士がつながって 1 つの塊に見えていた。
