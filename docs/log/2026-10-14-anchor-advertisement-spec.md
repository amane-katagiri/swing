# アンカー広告の仕様案

## 決めたこと

- 4001 を開けない参加者が多い前提で、NAT の内側のノードどうしでもサイトを渡せるよう、外から直接接続を受けられるノード（アンカー）を Nostr で広告し、NAT の内側のノードがアンカーへ接続を張り続ける仕組みを足す。公開の中継は Bitswap のデータを運ばないので、接続を受けられないノードどうしはホールパンチが失敗するとやりとりできない。NAT の内側から張った接続は双方向に使えるので、アンカーはその接続でホールパンチ無しに取得できる。
- DHT との違い: DHT はプロバイダーやアドレスを探せるが、接続そのものは作れない。張り続けた接続があれば、Bitswap が接続中の相手に先に問い合わせるので DHT を引かずに見つかり、NAT の内側のノードの告知が遅れたり失敗したりしても取得できる。誰とつなぐかを Nostr の身元（ミラー対象リスト）で絞れるのも DHT には無い点。
- 広告には PeerID だけを入れ、IP アドレスや multiaddr は入れない（MUST NOT）。アドレスは PeerID から peer routing で引ける。Nostr の公開鍵と IP アドレスを結びつけて公開しないため。
- kind は 35982（addressable）。`d` は PeerID で、1 人が複数のノードを持てる。`reachability` を `public`／`private` にし、届かなくなったら期限を待たずに `private` で置き換える（レプリカ報告の空の `cid` と同じ考え方）。止まったノードの広告が枠を取り続けないよう、`expiration` は必須にした。
- 受信側は自分のミラー対象リストに含まれる広告者の広告だけを使う（SHOULD）。libp2p の接続は相手の PeerID を鍵で確かめるのでなりすましはできないが、広告者は他人のノードの PeerID を書けるため。
- 選び方は受信側のポリシーとし、仕様には規範でない例として書いた。相互の関係の広告者を先に選ぶ（SWING ではフォローがミラーなので、相互の相手は自分のサイトを取りに来る相手で、身元も信頼できる）。残りの枠は、レプリカ報告から各アンカーが保存しているサイトを求め、まだ覆われていない自分のミラー対象のサイトを最も多く持つアンカーから貪欲に選ぶ。
- この実装の方針: 外から届くと判定されたら既定で広告を出し、設定でやめられるようにする。張り続ける接続の上限は既定 4 本。有効期限は 3 日で 1 日ごとに出し直し、届く・届かないの揺れで広告が変わらないよう、状態がしばらく続いてから広告を変える。
