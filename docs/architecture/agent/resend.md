# 保存した版のサイトイベントの再送（`agent/resend.rs`）

[`../agent.md`](../agent.md) の子ページ。保存している版のサイトイベントを、それを持たない relay にだけ送り直す（規則は [`../../protocol.md`](../../protocol.md#9-サイトイベントの送り直し)）。relay ごとの取得は [`../nostr/fetch.md`](../nostr/fetch.md#relay-ごとの取得)、取り下げの記録の形は [`state.md`](state.md#withdrawn)。

## 確認の間隔とタスク

- 確認はレプリカ報告の回のタスクの最後で、報告の同期と記録（`sync_reports_in_round`・`record_replica_reports`）を終えてから行う（`Agent::start_report_round` → `begin_report_round`）。poll は Follow Set が決まって過去分の取得まで終えたら、その poll の対象 pubkey を渡す。Follow Set が決まらない poll では確認を始めず、報告の回だけを始める。
- 起動してから一度も確認していなければ必ず始め、そうでなければ前回始めたときから `RESEND_CHECK_INTERVAL`（1 時間）以上たっているときだけ始める。間隔を確かめるのは poll（ダッシュボードでの mirror 変更による poll を含む）のときだけなので、実際の間隔は `poll_interval` の単位に切り上がる（例: `poll_interval` が 25 分なら 75 分ごと）。前回の時刻はメモリにだけ持つ。
- 前回の報告の回のタスクがまだ動いていれば（報告の途中でも確認の途中でも）、報告の回も確認も今回は始めず（debug）、確認の前回の時刻も変えない。間隔の確認と前回の時刻の更新は、タスクを始めると決めたときに行う。報告の回が長引くと（署名アプリの応答が遅いときなど）、そのぶん確認も遅れる。
- タスクは agent の終了で中断する（[シグナルと終了](../agent.md#シグナルと終了)）。

## 手順

1. 対象を集める。state の `sites` のうち、作者が対象 pubkey にいるサイトの、最新の版の `event`。対象 pubkey は、poll から渡されたもののうち、確認を始めた時点でも agent の対象（`Agent::replace_targets` で置き換える集合）にあるものだけ。`event` の無い版と、`remove_on_unfollow = false` で残している、フォローを外した相手のサイトは対象にしない。
2. 集めたイベントを state のロックの外で確かめ、次のものは除く。
   - 署名が正しくない、今の `[nostr].site_event_kind` のサイトイベントとしてパースできない、または作者と `d` が state のキーと一致しない（`nostr::saved_site_event`。debug）。
   - パースした `cid` がその版の `cid` と一致しないか、`created_at` が版の `created_at` より小さい（warn）。
   - そのサイトの記録した取り下げに当たる（`Withdrawn::covers`。debug）。
   - `[policy].nip05 = "require"` のとき、NIP-05 で検証済みでない（debug）。保存の順序と同じ `Agent::nip05_verified` で決めるので、キャッシュの期限が過ぎていれば検証し直して記録し、state を保存する（[`../nip05.md`](../nip05.md#agent-での適用)）。検証は `FETCH_CONCURRENCY`（4）件ずつ並行に行う。

   ここで送信のバックオフから、残ったイベントに無い `id` の組を消す（下記）。対象が無ければ終わる。
3. relay ごとに、対象のサイトそれぞれの最新のイベントを取得する（`RelayClient::fetch_sites_per_relay`）。
4. サイトごとに、relay の答えと保存している版を比べる（`nostr::plan_site_resends`）。
   - どれかの relay の答え（`Unfinished` の 1 件も含む）が NIP-01 の置き換え規則で保存している版より新しければ、そのうち最新のものを取り、info を出してどの relay にも送り直さない。その `cid` が保存している版と同じなら、そのイベントを保存している版のイベントとして state に入れ（`State::fill_latest_event`。次の確認からはそのイベントが対象になる）、違えば取り下げを state に記録する（`State::record_withdrawal`。形は `Withdrawn::superseded`）。
   - そうでなければ、保存している版と同じ `id` を返さず、「無い」か古い版を返した relay（`Missing`、または `id` の違う `Found`）に送ると決める。
5. 4 で送ると決めた relay のうち、そのイベントについてバックオフ中の relay を除く。どの relay も残らないサイトは送らない。送るサイトが無ければ終わる。
6. 送るサイトについて、作者の NIP-09 の削除要求（kind 5）を relay ごとに取得する（`RelayClient::fetch_site_deletions`）。
7. サイトごとに、全 relay から集めた削除要求に、作者自身の kind 5 で、`e` タグが保存している版の `id` のもの、または `a` タグが `<site_event_kind>:<作者 pubkey hex>:<d>` で `created_at` が保存している版の `created_at` 以上のものがあれば（`Withdrawals::of`）、info を出してどの relay にも送り直さず、その取り下げを state に記録する（`State::record_withdrawal`）。NIP-09 に従ってイベントを消した relay は 4 で「無い」になるので、この確認を省くと取り下げたサイトを送り直してしまう。
8. 残りのサイトは、5 で残った relay のうち、6 でそのサイトについて「答えた」relay にだけ送る。そうでない relay にはこの回は送らない（debug）。
9. サイトごとに、送る直前に（`FETCH_CONCURRENCY` の並行の枠が空いて、そのサイトを送り始めるときに）state のロックを取って次を確かめ直し、どれかが崩れたサイトは送らない（debug）。NIP-05 は記録した `status` だけを見て、ここでは検証し直さない。
   - 作者がまだ agent の対象にいる
   - `policy.nip05` が `require` なら、そのサイトがまだ NIP-05 で検証済み
   - state のそのサイトの最新の版が 1 で集めた版（`cid` と `event` の `id`）のまま
   - そのイベントが記録した取り下げに当たらない

   確かめたらロックを放して送る。送信は `RelayClient::publish_to` で、署名済みのイベントをそのまま、`FETCH_CONCURRENCY`（4）件ずつ並行に送る。送る前に info を出し、送信がエラーなら warn を、送れたがどの relay にも受理されなければ warn を出す。送信全体の期限は 120 秒で、過ぎたら warn を出して残りは次の確認に回す。

4 と 7 で state に書くのは、state のそのサイトの最新の版が 1 で集めた版（`cid` と `event` の `id`）のままのときだけで、変わっていたら書かない（debug）。記録が変わったら state を保存する。

| relay の答え（3・6） | 送り直すか |
|---|---|
| 保存している版と同じ `id` | しない |
| 保存している版より新しい版 | どの relay にもしない（4） |
| 保存している版より古い版だけ、または無い（未来ずれの許容を超えて先の版や、パースできないイベントだけの場合を含む） | 削除要求の取得に答えていればする |
| サイトの取得に答えていない（それまでに受け取った新しい版は上の行に数える） | しない |
| 削除要求の取得に「答えた」にならない | しない |
| どれかの relay に作者の取り下げがある、または取り下げを記録済み | どの relay にもしない |
| そのイベントについてバックオフ中 | しない |

- relay にある `cid` の違う新しい版は、ここでは版としては state に入れない。購読や過去分の取得で届いた新しい版は、保存するかに関わらず保存の順序の 1 で同じように記録する（[`store.md#保存の順序`](store.md#保存の順序)）。同じアカウントで処理中のサイトが多すぎて `submit` で捨てたイベント（[並行処理](../agent.md#並行処理)）は保存の順序に入らないので記録されず、次の poll の過去分の取得で拾い直したときに記録する。
- 取り下げの記録は送り直すかだけに効き、内容のミラー（購読・過去分の取得・保存の順序）は変えない。取り下げの後の新しい版は、保存すれば送り直しの対象になる。

## 送信のバックオフ

relay とイベントの `id` の組ごとに、メモリにだけ持つ（再起動で消える）。

- 送った relay が受理しなければ（拒否・時間切れ・送信のエラー）、失敗の回数を 1 増やし、`RESEND_CHECK_INTERVAL`（1 時間）× 2^(回数 − 1)、最大 1 日の間、その組には送らない。
- 受理したらその組を消す。
- 確認のたびに、手順の 2 で残ったイベントに無い `id` の組を消す。
- 9 の期限で送らなかった分は変えない。
