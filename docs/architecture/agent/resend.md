# 保存した版のサイトイベントの再送（`agent/resend.rs`）

[`../agent.md`](../agent.md) の子ページ。`agent::resend`（確認のタスクの起動は `agent/mod.rs`）。作者が送るのをやめた後で relay からサイトイベントが消えても新しい参加者がサイトを見つけられるように、保存している版のサイトイベントを、それを持たない relay にだけ送り直す（規則は [`../../protocol.md`](../../protocol.md#4-サイトイベント)）。

## 確認の間隔とタスク

- 確認はレプリカ報告の回（[`replicas.md`](replicas.md)）と同じタスクの最後で行う（`Agent::start_report_round` → `begin_report_round`）。報告の同期と記録（`sync_reports_in_round`・`record_replica_reports`）を終えてから確認に入るので、両方の relay への取得が重ならない。poll は Follow Set が決まって過去分の取得まで終えたら、その poll の対象 pubkey を渡す。Follow Set が決まらない poll では確認を始めず、報告の回だけを始める。
- 起動してから一度も確認していなければ必ず始め、そうでなければ前回始めたときから `RESEND_CHECK_INTERVAL`（1 時間）以上たっているときだけ始める。間隔を確かめるのは poll のときだけなので、実際の間隔は `poll_interval` の単位に切り上がる（例: `poll_interval` が 25 分なら 75 分ごと）。ダッシュボードでの mirror 変更による poll でも同じように確かめる。前回の時刻はメモリにだけ持つ。
- 報告の回のタスクは別タスクで行い、poll はその終わりを待たない。前回のタスクがまだ動いていれば（報告の回の途中でも確認の途中でも）、報告の回も確認も今回は始めず（debug）、確認の前回の時刻も変えないので、次の poll でやり直す。間隔の確認と前回の時刻の更新は、タスクを始めると決めたときに行う。署名アプリの応答が遅くて報告の回が長引くと、そのぶん確認も遅れる。
- タスクはほかの agent のタスクと同じく、agent の終了で中断する（[シグナルと終了](../agent.md#シグナルと終了)）。

## 手順

1. 対象を集める。state の `sites` のうち、作者が今の Follow Set の対象 pubkey にいるサイトの、最新の版（`created_at` が最大の版）の `event`。`event` の無い版（保存する前の形式で記録した版）は対象にしない。`remove_on_unfollow = false` で残している、フォローを外した相手のサイトも対象にしない。
2. 集めたイベントを state のロックの外で確かめ、次のものは除く。対象が無ければ終わる。
   - 署名が正しくない、今の `[nostr].site_event_kind` のサイトイベントとしてパースできない、または作者と `d` が state のキーと一致しない（`nostr::is_saved_site_event`。debug）。
   - パースした `cid` と `created_at` が、その版の記録（`VersionRecord` の `cid`・`created_at`）と一致しない（warn）。
   - そのサイトの記録した取り下げ（[`state.json`](state.md) の `withdrawn`）に当たる。`id` が `events` にあるか、`created_at` が `through` 以下（debug）。記録した取り下げに当たる版は、ここで除くので 3 以降の取得にも入らない。
3. relay ごとに、対象のサイトそれぞれの最新のイベントを取得する（`RelayClient::fetch_sites_per_relay`。打ち切り方と、作者・kind・`d`・パース・未来ずれの許容で除くものは [`nostr/fetch.md`](../nostr/fetch.md#relay-ごとの取得)）。
4. relay ごと・サイトごとに、relay の答えの最新の 1 件と保存している版を比べる（`nostr::plan_site_resends`）。
5. 4 で送ると決めた relay のうち、そのイベントについてバックオフ中（下記）の relay を除く。どの relay にも送らなければ終わる。
6. 送り直す予定のサイトについて、作者の NIP-09 の削除要求（kind 5）を relay ごとに取得する（`RelayClient::fetch_site_deletions`。作者ごとのフィルタと `limit`、「答えたか」の決め方は [`nostr/fetch.md`](../nostr/fetch.md#relay-ごとの取得)）。
7. サイトごとに、全 relay から集めた削除要求のうち、作者自身の kind 5 で、`e` タグが保存している版の `id` のもの、または `a` タグが `<site_event_kind>:<作者 pubkey hex>:<d>` で `created_at` が保存している版の `created_at` 以上のものがあれば（`Withdrawals::of`。作者と `id`・座標で引く索引なので、サイトごとの判定は削除要求の数によらない）、info を出してどの relay にも送り直さず、その取り下げを state に記録する（`State::record_withdrawal`。`e` なら版の `id` を `events` に足し、`a` なら `through` を削除要求の `created_at` との大きい方にする）。記録が変わったら state を保存する。NIP-09 に従ってイベントを消した relay は 4 で「無い」になるので、この確認が無いと取り下げたサイトを送り直してしまう。
8. 残りのサイトは、5 で残った relay のうち、6 でそのサイトの作者を含む REQ に答え、その作者が `limit` に達しなかった relay にだけ送る。そうでない relay にはこの回は送らない（debug）。
9. 送信は `RelayClient::publish_to` で、署名済みのイベントをそのまま、`FETCH_CONCURRENCY`（4）件ずつ並行に送る。送る前に info を出し、どの relay にも受理されなければ warn を出す。送信全体の期限は 120 秒で、過ぎたら warn を出して残りは次の確認に回す。

| relay の答え（3・6） | 送り直すか |
|---|---|
| 保存している版と同じ `id` | しない |
| 保存している版より新しい版 | しない |
| 保存している版より古い版だけ | 削除要求の取得に答えていればする |
| 無い（未来ずれの許容を超えて先の版や、パースできないイベントだけの場合を含む） | 削除要求の取得に答えていればする |
| サイトの取得に答えていない（その REQ に答えなかった、期限切れ、上限超え） | しない |
| 削除要求の取得に答えていない、またはその作者の削除要求が `limit` に達した | しない |
| どれかの relay に作者の取り下げがある、または取り下げを記録済み | どの relay にもしない |
| そのイベントについてバックオフ中 | しない |

relay にある新しい版は、ここでは state に入れない。過去分の取得で投入されて保存できれば、その版のイベントが記録される（[`../agent.md`](../agent.md#保存の順序) の保存の順序の 10）。取り下げの記録は送り直すかだけに効き、内容のミラー（購読・過去分の取得・保存の順序）は変えない。取り下げた後の新しい版（`created_at` が `through` より大きく、`id` が `events` に無い版）は、保存すれば送り直しの対象になる。

## 送信のバックオフ

relay とイベントの `id` の組ごとに、メモリにだけ持つ（再起動で消える）。

- 送った relay が受理しなければ（拒否・時間切れ・送信のエラー）、失敗の回数を 1 増やし、`RESEND_CHECK_INTERVAL`（1 時間）× 2^(回数 − 1)、最大 1 日の間、その組には送らない。
- 受理したらその組を消す。
- 確認のたびに、その回の対象（手順の 2 で残ったイベント）に無い `id` の組を消す。
- 9 の期限で送らなかった分は変えない。
