# 拡張時の命名規約と予約表

SWING のイベントを将来増やすときに名前がばらつかないよう、方針をここに固定する。

## 方針

1. NIP-51 のセット（kind 30000 など）の `d` タグは `swing` を接頭辞にする。区切りはハイフン。
2. 独自 kind は 35980 から連番でブロックを確保し、下の予約表に追記してから使う。
3. イベント間の参照は Nostr 標準の `a` タグ（`<kind>:<pubkey>:<d>`）で addressable event を指す。
4. 独自 kind には NIP-31 の `alt` タグを入れ、非対応クライアントでも人間向けの説明が出るようにする。

## d タグ（NIP-51 セット）

| d | kind | 用途 | 状態 |
|---|---|---|---|
| `swing` | 30000 | ミラー対象の pubkey 一覧（`p` タグ） | 実装済み |
| `swing-block` | 30000 | 絶対に保存しない pubkey 一覧 | 予約 |

## kind（addressable event, 3598x ブロック）

| kind | d | 主なタグ | 用途 | 状態 |
|---|---|---|---|---|
| 35980 | サイト識別子（通常はドメイン） | `cid` `url` `size` `title` `alt` | サイトの現在版 | 実装済み |
| 35981 | `<作者pubkey>:<サイトd>` | `a`（35980 への参照） `p` `cid`（複数） `expiration` `alt` | レプリカ報告（自分が保存している CID） | 実装済み |
| 35982–35989 | — | — | 予備 | 予約 |

## 標準の kind

| kind | 主なタグ | 用途 | 状態 |
|---|---|---|---|
| 1 | `a`（35980 への参照） | サイトを公開したことを知らせる通常の投稿（任意） | 実装済み |

## 参照の書き方

レプリカ報告や通常の投稿からサイトを指す例:

```json
["a", "35980:<作者pubkey hex>:<サイトd>"]
```

## alt タグの例

```json
["alt", "SWING site announcement: ama.ne.jp"]
```

この実装はサイトイベント（35980）に `SWING site announcement: <d>`、レプリカ報告（35981）に `SWING replica report: <d>` を付ける。

## 集計の想定

- 参加者一覧: `kind 30000` かつ `#d = ["swing"]` を relay 横断で取得
- Webring 表示: 上記の `p` タグから相互フォロー関係を作る（実装済み、`swing webring`）。relay 横断の全件取得ではなく、起点のアカウントから Follow Set と `#p` をたどる
- レプリカ数: `kind 35981` を `#a` でサイトごとに集計（実装済み、`swing replicas`）。作者ごとにまとめて取るなら `#p`
